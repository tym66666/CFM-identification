## 实际流程

```text
业务问题及原材料
  → 新候选A0（固定Skill与Schema）
  → 独立目标、字段与原文审核
  → 一份已审核意图及原文位置
  → 原事实读取：构造数学坐标、读取总体信息和科学声明
  → 原来源审核＋跨阶段意图一致性审核
  → 原科学审核、定理应用、证书重放
```

已接入政策均值、两政策差值、随机化局部直接/同伴效应、观察性网络政策四类事实读取入口。DAG仍保留其现有事实与审核路径；当前不通过此网络交接模块。数学覆盖没有因为改入口而增加。

## 每项内容由谁负责

|内容|唯一业务含义持有者|事实阶段的职责|
|---|---|---|
|问题、比较方向和两端安排|已审核A0逐问记录|构造现有合同需要的政策向量或局部状态；不能改成另一个比较|
|评价名单与平均方式|已审核本问的评价范围、权重表达|将已给出的对象映射成坐标；“全体”不能补出材料未提供的名单|
|处理和编码依据|A0处理说明及其实际原文位置|核对明确编码；A0没有形式化编码时仍须读取，不能默认使用=1|
|结果、时期、固定背景及共同条件|已审核逐问字段，保留UNKNOWN/MISSING|核对事实模型是否保持同一问题；不能把时期改成固定背景，不能把未知当作无条件|
|总体信息、科学条件、模型完整性|原材料＋事实草稿＋独立审核|不由A0批准，也不由意图交接自动补齐|

模块 `cfm_id_llm/reviewed_intent_handoff.py` 保存选定问题的一份原始含义，保留状态、原文区间和引用。两阶段的 `s0001` 不一定指同一句，因此按同一文档的字符区间映射来源编号；无法完整定位就停止，不按词语相似度寻找替代来源。

事实请求使用该份意图，去掉之前同时发送的规范化摘要和政策兼容别名。原业务材料仍完整提供。意图交接本身不是可引用事实；模型引用的仍是原文。

## 审核与恢复

- 网络新入口强制要求来源及交接一致性审核；省略审核不会进入求解。
- 工作表把已审核目标、范围、编码依据、时期和共同条件放在事实候选旁。原有`field_role/value_state/source_coverage`决定继续、待确认或拒绝。
- 不按文本相等自动判断业务等价。语义核对仍需要独立审核；若审核人错误接受，系统不能凭哈希证明其判断正确。
- A0、材料、事实回答或审核改变后，旧绑定不能沿用。事实重读保留原意图，但生成新的请求绑定，并要求审核全部变化。
- 不修改模型原答，不补引用后算模型成功，不把A0通过当作科学批准。
