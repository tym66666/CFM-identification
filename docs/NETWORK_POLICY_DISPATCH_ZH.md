# 网络固定政策均值：共同业务入口

用户描述原试点和想评估的安排，例如：“原来五个网点每次随机启用四个，现在如果全部启用，所有网点的平均完成率能否确定？”用户不必选择 R1b、R2 或预期结果。共同入口先保留目标，再检查各方法的条件。

本接点使用原生求解器和独立验证器，没有修改数学 Core、Estimation 或 Policy。它接通的是固定完整安排下的等权政策均值；其他网络目标仍保留原生能力，并明确报告当前业务桥尚未连接。

两端固定政策的有向均值差现由[共同比较接点](NETWORK_CONTRAST_DISPATCH_ZH.md)处理，复用本页的共同事实及模型检查；本页的单政策目标定义不变。

## 各层做什么

| 层 | 当前职责 |
|---|---|
| `business_intake` | A0 读取业务目标与研究结构，保留原问题及材料，不选定理 |
| `business_dispatch.prepare_reader` | 独立意图审核后，识别为对象网络中的固定政策均值，准备共同事实读取请求 |
| `cfm_id_llm/network_policy_reading.py` | 读取网络、原分配、完整未来安排、评价名单、总体信息与条件声明；返回短原文编号，不输出许可 |
| `network_policy_dispatch.inspect_methods` | 检查缺项、保留限制；符号信息准备 R1b/R2，明确数值有界模型交给 `network_bounded_dispatch`；不调用求解器 |
| 独立读取、科学和计划审核 | 核对原文含义、A1 坐标、A4 范围、A5 及其适用对象；每项 PENDING / ACCEPTED / REJECTED |
| `network_policy_dispatch._execute_plan` | 全部拟检查分支审核通过后才构造原生许可，调用已有求解器并独立重放，核对返回证据与实际审核输入一致 |
| `business_case` | 逐问汇总，保留未完成项；同样适用于已接通的 DAG 目标 |

共同入口仍是 `business_intake`；`NETWORK_FIXED_POLICY_FACTS` 是内部读取合同标识，R1b/R2 是后续数学方法，不是新增的用户菜单。

## 同一目标，两种识别条件

完整政策向量为 (z)，明确评价对象集合为 (S)，其余对象权重为零：

\[
V(z\mid w)=\frac{1}{|S|}\sum_{i\in S}E[Y_i(z)\mid W=w].
\]

原设计、可用总体信息和科学假设改变时，这个目标的身份不因此改变；它们分别绑定到证书。改变评价集合、政策向量或结果含义则是换了目标。

| 方法 | 在共同基础条件之外还需要什么 | 不允许的推断 |
|---|---|---|
| R1b | 完整政策事件 (q(z)>0)，以及覆盖正权重节点的完整处理向量条件总体均值或更强总体分布 | 把暴露组均值当成完整处理向量均值 |
| R2 | 对目标节点、所有完整二元安排成立的均值暴露充分性；每个目标签名正支持；对应总体信息 | 因为定义了同伴暴露，就默认均值充分性成立 |

共同基础条件包括已知分配律、完整向量随机化、一致性、处理前固定网络、所需条件一阶矩有限。模型从原文读到“拟采用某条件”只生成声明；独立科学审核后才可形成原生 ADMITTED 记录。没有审核、待定或拒绝时，不能先运行另一条方法绕过。

两种方法都成功时，`answers` 保留两份公式与证据；首份仅按稳定顺序展示。每个答案保存完整的 `native_evidence`，并记录原生输入摘要。执行始终重新检查当前材料、候选和审核；保存的成功标记不能代替证明。

原生数学合同见 [R1b](R1B_VERIFIED_FULL_ASSIGNMENT_POLICY_ZH.md)、[R2](R2_VERIFIED_MEAN_SIGNATURE_POLICY_ZH.md)。这里只组织这些已实现的定理，不声明新理论。

## 当前明确范围

- 固定、完整、简单无向对象网络；单时点二元处理；二元或连续结果。
- 原分配已连接 D1–D6：逐对象独立抽签、全体固定名额、两组名额、簇抽签、多组名额与两阶段名额混合；精确参数和科学条件见[设计/暴露入口](NETWORK_DESIGN_EXPOSURE_ENTRY_ZH.md)。
- 明确完整处理名单，明确全体、指定子集或单个对象的评价名单；当前业务桥要求等权平均。
- R2 已连接 E1–E5。核心名单、三档比例及多值人数按实际定义传递；没有从笼统“局部影响”推断定义或充分性。D6 另需独立审核第一阶段方案的直接影响排除条件。
- A4 支持符号完整联合总体分布、各节点结果与完整处理向量的总体分布、列明完整向量的节点均值，以及列明节点/自身处理/暴露格子的总体均值。来源不合并成一份更强信息；是否足够由原生检查决定。
- 有限样本保持样本身份。精确签名均值与明确界限可进入下述有限有界合同；完整分布不会被压缩为几个均值，额外依赖、单调或方法限制保留并阻断未连接的模型。

两个图的描述同时出现时，仍须明确单位关系图和变量 DAG 如何共同建模；不会自动丢掉其中一个。政策差值使用上述比较目标合同；随机政策、最优政策、多期或动态网络仍不硬套当前合同。

## 停止状态及 PARTIAL 接点

目标、总体信息或声明缺项返回 NEEDS_INPUT；无效来源、过期或错范围审核返回 CHECK_BLOCKED；其他结构或额外限制返回 ADAPTER_NOT_CONNECTED。现有方法均不适用时明确保留原因，且 `nonidentification_proved=false`。

模型自由文本备注先经 [独立备注审核](READING_NOTE_REVIEW_ZH.md)，不能一律当作用户缺项。解释性或数学判断备注经原文复核后只允许继续检查；真实缺项仍阻断，读取错误须重读。原候选不修改，备注决策绑定后续计划与科学审核。

若所有已列信息均明确为有限样本，优先报告总体信息尚未声明（NEEDS_INPUT）。即使模型在自由文本中重复写入样本限制，原文、附加限制及其他未接入原因仍完整保存；补齐总体信息后，剩余附加限制仍须单独处理，不能借此跳过审核。

特别是 (q(z)=0) 只是 R1b 不适用；R2 的目标签名零支持也不能直接生成区间。当前新桥不自动调用 PARTIAL，不补造界限或总体数值。

现已连接 [有限政策均值数学合同](BOUNDED_POLICY_MATH_ZH.md)，由 `network_bounded_dispatch` 直接复用原数值求解器与独立验证器。该合同从明确的模型声明进入，不是 POINT 失败后的自动降级：

1. 原设计 D2，暴露 E1，最多 12 节点，覆盖全部节点、全部二元安排的均值充分性。
2. 一份完整列明的精确总体签名均值清单；每个格子都有数值，不是样本估计。模型可以将同一个原文文档的表拆成多个信息条目，程序仅拼接不重复的精确格子，并保存全部原条目和审核；不合并来自不同文档的数值表，不平均或去重冲突格子。一份信息条目同时引用数值表和辅助定义时，须完成下述独立来源审核。正支持目标签名缺数值仍为 NEEDS_INPUT。
3. 全节点明确界限，区分均值界与潜在结果本身的界限，保留结果定义、单位、期间和适用范围；二元结果也不由读取器默认补界限。
4. 另行声明并审核“总体信息只有这些均值”和“没有额外耦合限制”；没有提及其他条件不等于明确排除它们。

以上读取仍不等于审核通过。完整条件绑定到单独的科学审核项目；当前数值接点沿用原有 **SYNTHETIC_TEST 合成研究范围**，外部研究权限不会自动升级进入。输出保留 `production_admission=False`，不是现实假设认证。

界限退化可返回数值 POINT；有宽度则返回相应模型的 sharp PARTIAL，并分别标注 informative。INCOMPATIBLE 仅为原生诊断，不伪造不可行证书。求解前后和重放前后都核对输入摘要，拒绝另一模型的证书或求解过程中的输入修改。

例如七个星形网点每轮均匀启用三个，评价全员启用时的等权均值；六个外围网点的目标均值为 1/2，中心目标没有支持。其余模型和 A4 不变，中心均值界依次为 [1/2,1/2]、[1/4,3/4]、[0,1]，结果依次是 POINT 1/2、sharp [13/28,15/28]、sharp [3/7,4/7]。这是科学界限逐步放宽；缺少模型声明属于信息未齐，不能把这种停止状态说成数学上已证明不可识别。

整题汇总同时保留 `point_identified_query_ids`、`partially_identified_query_ids`。`ALL_QUERIES_IDENTIFIED` 允许经重放的 sharp PARTIAL；是否全部为 POINT 必须查看 `all_queries_point_identified`，不能混同。

## 一份信息表及其辅助说明

“精确数值来自一份表”不等于“该信息条目只能引用一个文档”。例如表格给出各站的总体均值，另一份材料定义表中的邻居标记；后者是必要的解释来源。不能要求 LLM 删掉这条有效引用来通过适配器。

[network_information_evidence.py](../cfm_id/network_information_evidence.py) 为这种情况准备独立来源工作表。它仅接受一个 `NODE_SIGNATURE_MEANS`、`EXACT_POPULATION_VALUE` 信息条目，且该条目引用多个文档。审核人逐条区分：

- `table_source_ids`：提供全部精确格子的来源，必须属于同一个原文文档。
- `supporting_source_ids`：只解释对象、编码、暴露或期间的来源，不能包含另一份总体信息、方程或额外限制。

两组必须不重叠，完整覆盖该条目的所有真实来源编号，不能漏掉不方便的引用。引用使用工作表中的完整来源编号；不是随意填 LLM 的短编号。来源角色判断由审核人根据全文作出，程序只检查结构、范围和当前绑定，不自动证明语义正确。记录为 PENDING 或 REJECTED 时不能进入后端。

审核绑定原文、实际候选、事实请求和已审核目标；变更任一内容，旧记录失效。它不修改候选、不合并信息条目、不增加数学约束，也不授予业务或科学许可。通过后仍要完成原有计划、读取和科学审核。未提交此记录时，旧行为保持不变；多份真实数值表、额外耦合或尚未支持的信息类型仍不能借此进入当前模型。当前有限数值合同继续仅在 SYNTHETIC_TEST 范围执行。

公共 Python 接口在 `business_dispatch.inspect_methods` / `execute` 中接收可选的 `information_evidence_review`。离线 CLI 的 `information-evidence-plan` 只导出工作表，`method-plan` / `execute` 接收 `--information-evidence-review`，见 [业务分派接口](BUSINESS_DISPATCH_ZH.md#本地接口)。不需要额外 LLM 调用。

## 运行

共同单问和整题 CLI 沿用 [业务分派接口](BUSINESS_DISPATCH_ZH.md) 的命令，读取合同由审核后的研究结构和目标决定，不增加 `--method` 或 `--lane` 参数。网络读取使用 `short_refs`；历史长来源格式须显式切换并重新读取，旧回答不会自动修复。

离线合成例子：

```powershell
python -m examples.network_dispatch_reference --allow-synthetic-reviews --output outputs/network_dispatch/reference_001
python -m examples.network_bounded_dispatch_reference --allow-synthetic-reviews --output outputs/network_dispatch/bounded_001
```

输出目录必须为新目录。它展示 R1b、R2、两者同时成立及支持缺口；是显式的合成审核，不是模型准确率或现实假设证明。定向验收文件是 `tests_gateway/test_network_dispatch.py`，也纳入固定框架验收清单。
