# 维护入口与新增能力的验收义务

当前源码唯一位置与目录地图见 [开发入口](DEVELOPMENT_ENTRY_ZH.md)。本页用于判断修改落点，不增加数学分类、自动插件发现或普通用户必须选择的路线菜单。

## 当前应用入口与兼容入口

| 用途 | 使用位置 | 维护约定 |
|---|---|---|
| 新业务进入系统 | `cfm_id.project` → `business_intake` → `business_dispatch` → `business_case` | 固定加载包内 `configuration/reading.json`；用户不预选数学方法 |
| 已有数学能力登记 | `cfm_id.capability_registry` | 数学能力、共同入口、专门会话分别登记；登记不是科学许可 |
| 事实读取组件登记 | `cfm_id_llm.fact_reading_contracts` | 八类 short_refs：政策均值、两政策差值、随机化局部效应、R3 观察性政策、变量 DAG、单个随机化臂均值、有限政策混合、观察性效应；配对请求、解析、来源、诊断、条件交接与重读 |
| 推荐配置 | `cfm_id/configuration/reading.json` | 新应用只用这一处；复用已有协议，不声称首读最优 |
| 兼容默认 | `ReadingConfig()`、`examples/legacy/configs/compatibility_default.json` | 不改变旧请求和旧检查点，不作为学生起点 |
| 历史实验 | 显式旧配置（参见[配置指南](BUSINESS_READING_CONFIG_ZH.md)；历史实验记录不随个人仓库发布） | 用于显式复现；不能按版本号大小决定采用 |
| 旧显式入口 | `business_entry`、`intent_submission`、内部 `workflows.legacy_network` | 保留兼容；新运行代码不得依赖参考答案 |

共同登记只收拢组件拥有者，不代替各家族的业务和科学审核。旧 hash 来源 DAG 仍是兼容适配分支。逐问背景、固定条件和标准化目标的合同见 [目标条件职责](TARGET_CONDITIONING_OWNERSHIP_ZH.md)；未接入的明确条件目标继续阻断。

## 公共工具的归属

方法诊断由`method_diagnostics`维护，中文条件标签与方法范围说明归`method_requirements`，可执行成员仍只消费`capability_registry`。已有固定政策均值和两政策差值样板；`contrast_diagnostics`仅适配差值的两端尝试、组合证据与联合界限记录。扩展时复用实际原生工作表和失败记录，不复制数学支持判据，不用状态标签替代证书，不把缺项清单称作最弱假设；共同模型、额外限制和旧审核失效仍由原执行链处理。不同证据形状要明确适配并测试：单端成功不能代替比较成功，联合界限不能当作独立端点区间相减。具体接口及证据边界见[方法诊断合同](METHOD_DIAGNOSTICS_ZH.md)。

局部直接/同伴效应的记录适配位于`effect_diagnostics`：共享审核与来源流程，单独保留局部状态、原设计条件平均、固定评价范围和ANCHOR/组合阶段。新增形状时要验收“局部成功但整体失败”、方向/名单改变导致旧审核失效、错误证据拒绝展示；不得把命名直接效应、反向线性效应、固定政策差值混成同一目标。条件标签以原生常量为依据，D6等条件性科学义务从实际工作表获取。

R3观察性完整政策的记录适配位于`observational_diagnostics`：完整政策、评价名单和固定W分别绑定；保持条件交换性的独立科学审核与跨阶段固定背景审核。正支持只转述原执行器对完整安排的联合概率检查；不能用边际支持或完整表声明替代，也不能由零支持推出一般非识别。原生研究摘要绑定scope/protocol，不能当作整个研究对象的内容哈希。

来源绑定的材料交接由 `reading_material_handoff` 维护，材料完整性与识别影响审核由 `reading_impact_review` 维护；`fact_source_review.prepare` 按显式会话合同选择工作表，CLI 不另维护一套审核逻辑。新增读取族不能直接继承“纯估计说明不阻断”的窄范围判断，须证明其字段依赖及原生适用域，并提供缺项、错误来源、复查与证书验收。当前范围及限制见 [材料交接验收](READING_MATERIAL_HANDOFF_ACCEPTANCE_ZH.md)。

政策均值／两政策差值的可选引用接口及补齐条件覆盖名单的 `network-policy-record-definitions-1` 见[共同读取登记](FACT_READING_REGISTRY_ZH.md#可选的政策定义引用样板)。共用解析由 `policy_evidence_dependencies` 维护；新协议只声明扩展的记录与 Schema，旧协议请求不变。它区分直接主张与显式定义依赖，尚不升级默认；语义漏读仍须阻断。新接口的维护者不得把定义来源合并为新的总体信息来源，或自动补填政策与覆盖名单。

新增仅改变说明的配置，也必须验证完整链路的能力挂接，而不能只测试 Schema 相同。逐问条件现在通过登记合同的 `target_context` 能力进入分派；须提供该合同的目标作用域检查和缺项问题，并验收首次、后续请求、原生审核、恢复和拒绝路径。S82 的安装检查曾发现按单一历史协议名判断导致条件漏接；此类扩展不得默默丢弃目标上下文。

| 工具 | 归属与适用范围 | 禁止混用 |
|---|---|---|
| 材料表、原文片段、来源编号、文件字节摘要 | `cfm_id.materials` | 运行调用必须明确提供材料根目录，不自动找 Benchmark |
| 当前结构化 JSON 摘要 | `cfm_id_llm.orchestration_schemas.canonical_sha256` | 拒绝非有限 JSON 数值；不是对任意 Python 对象的序列化 |
| 数学/科学类型的规范化与摘要 | `cfm_id_bridge.scientific_binding.canonical_data`、`sha` | 保留 Fraction、dataclass、模型等已有类型规则；不替代科学许可或身份签名 |
| 历史普通 JSON 摘要 | `cfm_id.serialization.canonical_hash` | 仅保持旧网络协议字节兼容；包括旧 JSON 的非有限值行为，不能冒充严格新合同 |
| 字段语义、引用责任、请求/解析配对 | `business_field_contract`、`source_coverage_contract`、`network_fact_protocols` | 不根据题号补值、按答案回填引用或自动批准 |
| 信息字段组合 | `information_field_rules`（政策读取）、`effect_information_rules`（局部效应读取） | 同一公开规则用于 Schema、解析和复查诊断；字段相容不等于来源语义正确，不能自动改写模型回答 |
| 均值顺序字段及重复定义 | `mean_order_field_contract`，由读取、Schema 与诊断共用 | 结果定义和编码不能跨字段变义；明确拟采用的关系、尚未决定和不采用分别表达，科学批准仍独立；额外约束不能被自动删除 |
| 局部效应的信息与剩余主张职责 | `network_effect_reading.RESIDUAL_ROLES`，共享到 Schema 描述与请求元数据 | 按主张保留未表达内容及来源；只是公开读取说明，不能当语义验证器或自动删除约束的许可 |

本次不合并不同摘要算法。即使常见输入摘要相同，允许的输入类型、非有限值规则和历史协议也可能不同。新增通用工具优先使用既有明确合同；确需新合同，应说明输入类型、错误行为、绑定用途和兼容策略。

## 数学材料的维护归属

详见 [数学与证据导航](MATH_AND_EVIDENCE_ZH.md)。文献卡维护阅读范围；项目数学文档维护完整模型与推导；`mathematical_contracts.json` 只链接合同和实现；可执行覆盖只在 `capability_registry` 登记；实际成绩写带日期的验收记录。新增连接同时更新索引与 S77 一致性检查，不将历史研究状态复制成当前覆盖。新组合工作流放在 `cfm_id/workflows`，不能复制原生求解器或把合成批准带入运行代码。

## 新能力应交付什么

| 改动类型 | 首要代码/材料落点 | 必须提供的证据 |
|---|---|---|
| 已有含义的新业务场景 | `evaluation` 的公开材料与私有参考，必要的 `examples` | 完整自然语言、来源、冻结目标与正负例；不能按题号改运行分支 |
| 读取格式或说明 | 对应 `cfm_id_llm` reader、公开 Schema、请求/解析配对与诊断 | Schema 与解析一致；未知、额外限制、来源保留；请求变更使旧审核失效；另测真实模型 |
| 已有数学能力接共同入口 | 专属业务适配器、`capability_registry`，需要时更新共同目标分派 | 目标/A4/A5 精确绑定；缺项、拒绝、撤回、错配、伪造成功结果的负例；实际原生计算与独立 replay |
| 新数学方法 | 专属 contract、solver、independent verifier，以及 `literature_support` | 明确目标、总体信息、科学模型、适用域；推导和适用文献；证书义务、反例及边界；完成后再接业务层 |
| 假设放宽比较 | `research_versions` 及对应数学合同 | 保持目标与信息一致，说明模型包含关系；每版独立审核与证书；sharp 相对于该版完整模型 |

网络干扰与变量 DAG 是研究结构；D 是分配设计，E 是暴露定义，R 是识别机制。新增内容先明确属于哪一层，不为每个业务题复制一整条读取、审核、执行、展示链。

数学义务不能只靠通用回归通过：POINT 需核对目标与可观测泛函；PARTIAL 需分别说明有效界和 sharpness，联合差值不能以两个独立区间机械相减代替；非点识别需在声明模型内构造可核对反例。支持/正性、退化情形、不可行模型与未覆盖状态分别测试。独立 replay 不等于形式证明助手，也不证明现实假设为真。

迁移读取登记时，除了直接请求一致，还须对照重读后的实际请求：既有方向说明、目标交接和配置不能在重建请求时丢失。发现旧交接错误时应明确记录兼容例外，阻断受影响的旧请求与批准；不能只为摘要一致保留已知错误。两政策差值须分别验收反向比较、共同评价范围冲突、联合模型及共享未知量抵消，不以两端各自通过代替比较审核。

## 变更验收顺序

执行层级及去重规则见[测试指南](TESTING_ZH.md)。先跑相关测试和quick，连接／审核改动再跑chain；一组改动收尾或发布前跑full。合并时保留每项数学、审核与证书义务的明确维护位置，不以减少计数作为验收标准。

1. 冻结当前请求、材料、审核、结果与受保护源码；先记录真实的基线问题。
2. 新运行代码不得依赖评测答案、合成审核生成器或默认 Benchmark 路径。历史 `evaluation` 导入保留兼容，但正式运行依赖归零的检查不能放宽。
3. 定向正负例和旧协议恢复通过后，更新 `evaluation/framework_acceptance.json` 的实际 pytest 节点；运行整体离线回归及源码之外的安装检查。
4. 只有说明/读取行为需要真实模型检验时才调用 API；冻结未参与调试的完整业务。分别报告传输、格式、语义、引用、审核后执行，首答与复查分开，不因负例安全阻断便把它记为完整读取正确。

这是维护规则，不要求每次修改都重新训练模型、重建数学 Core 或运行无关的下游实验。发现错误时修对应层，保留证据，不降低准入要求。


新增读取格式如替换已有字段归属或引用表达，须同步核对首次 Schema、解析器、逐字段工作表、类型诊断、显式重读、完整变化审核和实际配置组合。新协议已经替换的公开区块，不能被继承的旧配置再次强制要求；旧配置仍须重建相同历史请求。数据类型映射须写明数学上使用哪个模型、保留哪些业务限制、哪些结论不能转移。本轮 COUNT 示例只转移较大可积实值模型的 POINT 恒等式，不转移非识别或 sharpness。

新增逐问调用参数还须检查整题提交白名单、检查计划与执行的参数传递、保存恢复和CLI序列化。`test_whole_case_information_evidence`将单题执行输入与整题输入集合对应起来，避免新增审核只接一端；运行仍使用显式白名单，不通过反射接受任意参数。每份审核只属于当前问题及绑定，不能扩展成全局批准。固定背景与标准化目标见[TARGET_CONDITIONING_OWNERSHIP_ZH.md](TARGET_CONDITIONING_OWNERSHIP_ZH.md)：显式 `query-conditioning-1` 已接入首次读取、审核、R3 条件绑定和重读，旧默认不变。


## 局部读取配置与字段职责的共同登记

局部 A0 协议的模块配对只在 `cfm_id_llm.compact_response_contract.LOCAL_PROFILE_MODULES` 登记；请求、配置、审核和诊断消费其派生分组。Schema 的 Literal 枚举仍须显式声明，新配置须有注册／工厂一致性测试。模块只来自源码封闭登记，不接受调用者提供的任意导入路径；它不是数学能力目录或用户路线选择。

修改某个字段含义，应让首次 Schema、公开复查帮助（含 value/refs 嵌套路径）和逐字段审核消费同一定义，不能在三个位置各追加不同提示。`local_population_contract` 是本轮对齐示例；旧 profile 的历史请求必须逐字可恢复。事实配对需要声明 FACT_VERSION，并核对真实分派、解析、重读和安装入口。

公开说明改变不等于审核放宽：所有原文明示限定仍须保留，实际引用须支持所属字段，完整变更须重新审核。无形中借 goal 补 target_population、借名册补样本范围、借编码定义补目标选择，都不能通过。新 profile 只有通过冻结的新题重复验收后才考虑提升默认，不能按编号大小决定推荐项。当前公开验收见[发布记录](RELEASE_ACCEPTANCE_ZH.md)，各轮原始实验另行保留。

## 读取调试的预算与停止边界

字段合并必须有单一拥有者和显式兼容投影。例如 `single-action-target-1` 不再让模型重复提取主政策；原始回答与主字段状态、引用保持不变，兼容字段不得独立修改。信息记录的范围引用也不能混进原生总体信息表的来源列表，否则会虚构额外信息表。新增条件约束须同时核对首次 Schema、解析和重读诊断；只开放源码定义的错误码，不把不可信异常文本作为提示回传。

新一轮真实模型实验必须先说明要检验的通用问题、冻结业务、分母和调用上限；首答、显式复查、传输重试分别计数。一轮结束后不自动继续给失败题追加提示语版本。优先修复程序接口、来源绑定及审核边界；读取首答残留要如实披露，保留独立审核，而不是放松准入或无限期阻塞已有数学能力接入。

`local-role-ownership-4` 是本轮冻结局部效应实验配置，不替换兼容默认或早期政策配置。`cfm_id.reading_information_consistency` 处理已审阶段之间的声明矛盾，属于运行流程；它不属于 Prompt、不读取自然语言，也不是总体信息的科学验证器。


来源审核扩展见[事实来源合同](FACT_SOURCE_REVIEW_ZH.md)。新增事实字段要说明其归属、未知状态、直接引用及显式定义依赖；整份材料完整性另审，不能靠只展示已填字段证明无遗漏。格式模型由 `fact_wire_models` 按已有请求/解析配对选择；各 short_refs 事实家族均消费 `fact_reading_contracts` 为其登记的格式模型，不能另建不一致的宽松模型。`source_review` 为显式调用参数；下游审核必须绑定原答和该记录。新来源规则不自动补写候选，不得把来源审核升级为科学批准。
