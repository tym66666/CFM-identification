# 现阶段网络干扰 POINT 覆盖范围与 A0 合并准备度（P1.1）

## 结论

**不能说已经覆盖“大多数现实网络干扰问题的点识别”。** 未定义业务任务抽样总体/分母，已覆盖合成展示和定理组件数量不能转化为现实覆盖率。即使只谈在某些因果假设下 POINT 可识别的任务，模型类型仍远比当前有限子域广泛。

目前可严谨宣传：**较完整地覆盖一个限定范围内的 Network-first POINT 系统**：已知处理前固定简单无向图、单时点二元 treatment、均值型目标、D1–D6 的已知随机设计或 R3 中几种限定观测总体律；A4 是充分的 typed 总体算子；A5 已经有独立科学依据并被接受；A6 正支持逐目标核对；不要求真实数值 Estimation。

## 当前正式能力（截至本增量）

- **四个主要数学机制**：R1a 设计标准化随机实验 arm，R1b 正支持完整政策，R2 经确认均值签名充分性的政策外推，R3 已声明交换性下的观测政策/标准化 arm/分层调整。
- **10 条正式业务路线**，不是 10 个互不相关的因果识别理论。新增条件混合 A4 不增加 Route。
- **6 类设计 D1–D6 × 5 类 Exposure E1–E5**；在各自有效域内至多 30 类参数组合。特定网络和 arm 可能零支持，不是 30 种组合无条件全部 POINT。
- **11 项前提名称**（现有扩展目录）；其中一些属于 A4、分析条件或研究背景，不全部为新 A5 假设。新增条件混合处理律是 A4 表达能力，不增加 A5 数量。
- R3 有显式小网络分配律、nodewise factorized、p-standardized correlated mixture、共享 B 分层、nodewise X_i/邻居 X 计数分层。**这几种来源用于不同的因果目标，不可无理由互换。**

## 面向“POINT 可识别任务”的非代表性适用域清单

| 场景类别 | 当前软件结论 | 数学/输入限制 |
|---|---|---|
| 固定无向图的 Bernoulli / quota / cluster / two-stage 随机实验 | 正式支持 R1a/R1b/R2 | q、consistency、A4、每目标正支持，D6 特殊 A5 |
| 单时点 Direct/Spillover/Total 和合法节点权重 | 正式支持对应 R1a/R3 子域 | 标准化目标需明确，不能等同受控干预效应 |
| 正支持固定完整网络政策及已认证有限混合 | 支持 R1b | 完整 assignment A4 与 q(z)>0 |
| 结构均值充分性下 zero full-assignment support 的政策 | 条件性支持 R2 | 逐节点 signature 支持，强科学 A5 |
| 小型观测网络固定政策 | 有限支持 R3 | 显式总体律、full-vector 交换性、≤12 节点 |
| 大型观测网络 p-standardized effects | 在若干精确 A4 子域支持 | 全向量交换性，因子化或有限混合 |
| 大型观测网络 Nodewise Covariate Adjustment | 本轮已支持条件混合 A4 子域 | 二元 X_i+邻居正值计数；强局部 A5，最大 24 X profiles，每 profile ≤16 混合分量 |
| 一般观测选择关联，未知混杂/同质性 | **不能自动认证 POINT** | 分配律本身不证明无未观测混杂 |
| 任意高维本人/邻居 covariate GPS 调整 | 未实现通用 POINT 后端 | 不具备一般科学 A5 及 A4 契约 |
| 任意相关 p(T|X,W) 非参数/Auto-G | 未实现通用 POINT 后端 | 有限混合支持不等于一般 oracle |
| 处理诱导的网络变化/传播/时间序列 | 未实现 | 不在当前固定 G、单时点潜在结果模型内 |
| 有向/加权/未知图或网络测量误差 | 未实现通用 POINT 后端 | 现有 G 输入为已知简单无向图 |
| 多值/连续、多期 treatment | 未实现 | 全部主要正式输入为单时点二元处理 |
| 任意大规模 stochastic policy kernels | 尚未实现通用形式 | R1b 当前仅固定政策及有界有限混合 |
| 跨 W 层、跨人群/跨企业运输效应 | 未实现通用 POINT 后端 | 当前多路线仅固定 W=w 的研究语义 |
| 多级干预、鼓励/不依从、局部 IV | R5 未实现 | 特殊设计与额外因果 A5；按当前要求暂缓 |
| POINT 边界之外的 PARTIAL | R4 暂缓 | 不计入当前 POINT 范围 |

上述是**研究者选定的适用域诊断列表，不是来自实际企业任务分布的统计样本**，所以不能计算“x% 现实覆盖率”。

## 是否可以合并另一个 GPT 的 A0？

**可着手准备接口对齐，但不建议因为“已覆盖大多数 POINT”而直接合并全部业务自动化流程。** 建议 A0 输出只接入现有 typed public business inquiry（不走旧 legacy 入口），并区分 Proposed / Human Admitted 的来源、目标语义、处理前网络、A4 总体算子、A5 许可及 A6 适用域；不允许 LLM 根据观测数据自行宣称这些假设为真。A0 团队负责语义解析/确认，本模块只负责证明核对、证书与拒绝语义。

合并前 Gate：1) 提交固定的 v2.8 P1.1 ZIP 与全部回归；2) 用 15–30 张双方共同认可的真实业务**问题描述**组成协议契约评测集，人工确认 A1–A5；3) 逐条自动验收 `POINT / NEEDS_INPUT / UNSUPPORTED` 与适用域坐标，确保新场景没有偷添强假设；4) 对未实现案例明确说明能力限制；5) 统一 `schema_version` 和异常安全拒绝协议。可以先接 API 试运行，不能在没有 A0 人工接受流程的情况下自动认证科学假设。

## 本轮刻意不做

A0 本体、Estimation/PFN、R4 Network PARTIAL、R5 IV、通用 DAG 与动态图。理论背书是数学上的有条件识别，不是对现实研究设计有效性的认证。
