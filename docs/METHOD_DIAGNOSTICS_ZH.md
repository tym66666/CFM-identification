# 多识别路径检查与条件诊断

本页是对外部建议材料的修订和实际落地合同。当前实现的是**只读方法诊断与待核对清单**，不自动选择算法、不接受新假设、不改变执行许可，也不要求 LLM 更强。维护位置仍为唯一工作源码，未同步 GitHub 发布副本。

## 放在整体流程的哪里

```text
业务原文 → A0与事实读取 → 原文／目标审核 → 既有 inspect_methods
                                            ├─ 原有审核与执行 → 原生证书重放
                                            └─ 新诊断视图 ← 已有执行记录（可选）
```

诊断视图解释“当前有哪些已登记的方法、哪些进入了计划、缺哪些审核、哪些数学检查已运行”。它不是第二个识别器，不向执行器回写数据；读错或共同模型尚不清楚时，不会绕过上游检查去预测哪条定理能成功。

已接入固定政策均值的 R1b、R2、有限有界均值模型，两政策差值的 R1b/R2 两端组合与有限模型联合求界，以及 R1a 原设计条件平均的局部直接／同伴效应。R3观察性固定背景完整政策均值也已接入。DAG及其他原生R3目标尚未接入这份诊断视图；它们的原业务执行能力没有改变。诊断尚未连接某家族，不能解释成数学方法未覆盖。

## 三个维度必须分别报告

| 维度 | 实际来源 | 可以说什么 | 不能说什么 |
|---|---|---|---|
| 读取／科学审核 | 当前原生审核工作表及与之绑定的记录 | 待审、接受、拒绝、失效 | 审核接受不等于数学条件已经证明 |
| 方法计划与数学适用性 | 原生 `methods`、`exclusions`、`attempts` | 已列入计划、原生排除、尚未检查、原生报告不适用 | 尚未执行不能显示正支持已满足；路线失败不是目标非识别证明 |
| 执行证据 | 同一计划、目标和方法的已有 `answers` 与证书记录 | 原执行记录报告 POINT/PARTIAL 和 replay 成功 | 新诊断报告本身不是证书，也不再次执行 replay |

报告明确包含 `is_approval=false`、`is_certificate=false`、`grants_execution=false`。证据状态为 `REPLAY_REPORTED`，而不是诊断器独立发出的 VERIFIED。正式数学认证仍在原执行结果中。

`describe` 用于解释受维护的原执行记录，核对计划、方法、目标、重放标记和证据是否一致；它不能认证任意外部 JSON 的真实性。记录哈希也不是审核者身份签名。要新认证一个输入，仍调用原执行器和独立验证器。

## 条件清单如何维护

| 模块 | 职责 |
|---|---|
| `capability_registry` | 唯一可执行能力登记，决定显示哪些已登记方法 |
| `network_policy_dispatch`、`network_bounded_dispatch` | 原生计划、实际条件键与科学审核义务的拥有者；本轮执行语义不变 |
| `method_requirements` | 方法范围、中文标签和原生原因的解释；消费上述登记和常量，不计算支持或判断科学前提 |
| `method_diagnostics` | 把原计划、审核记录和可选执行记录整理成只读视图 |
| `contrast_diagnostics` | 共同诊断内部的差值记录适配：保留两端顺序、共同范围、端点尝试及联合求界证据形式；不调用数学后端 |
| `effect_diagnostics` | 局部效应记录适配：保留自身/同伴状态、评价范围、条件平均规则及分阶段执行证据，兼容原生命名效应与反向直接效应线性证书 |
| `observational_diagnostics` | R3完整政策记录适配：保留固定W、评价名单、交换性审核和完整政策联合支持；不推断随机化或跨W平均 |
| `project.diagnose_methods` | 从共同业务入口重建当前计划，再生成诊断；复用原有读取和来源检查 |

**实际审核项以原生工作表为准。** 模板只是解释，不能替工作表创建待批准项目或给条件赋真值。未知条件键、未知原因码原样保留，不猜测含义。未列入当前计划的方法显示 `NOT_PLANNED_FOR_CURRENT_INPUT`，不能把它们说成数学失败。

R2 的“暴露定义／均值充分性／覆盖范围未建立”目前仍是原生汇总诊断，新视图不会宣称每一项都缺失。有限模型缺项也保留原生追问，不另写一套与执行器竞争的资格判定。后续如果需要更细的诊断，应让原检查函数在实际失败处输出具体项目，再由视图消费。

`outstanding_review_items` 精确列出当前工作表中尚未接受的项目；`next_actions` 给出核对方向。它们不排序，不宣称找到了最少或最弱的科学条件。改变目标、信息或科学条件后，必须重新生成并审核当前版本。

## 对原建议材料的修正

1. 保留“同一目标检查多条已登记路径”的方向，但第一版只读现有结果，不增加自动尝试、自动降级或方法优先级。
2. “五个对象每次抽四个”不足以推断 R2 有正支持，还要给定网络和暴露。完全图配合启用邻居数时，目标启用节点要求四个启用邻居，而原设计最多三个，不能直接打勾。本次可运行正例则明确使用星形网络和严格多数暴露，由原生 Core 检查支持。
3. “必要条件”统一解释为**该已登记方法的适用前提**，不是目标可识别的全局必要条件。
4. 有限 PARTIAL 需要当前已实现模型的精确总体信息、界限和完整性声明；这不是所有部分识别方法的通用要求，也不能删除已有联合信息或耦合限制以进入该模型。
5. 暂不实现分支独立审核。当前 R2 待审时，已计划的 R1b 也不能提前运行；这条既有行为继续保留。未来改变它需要单独设计共同问题与各分支审核绑定，并验收撤回、过期、额外限制和跨分支绕过。
6. 不把外部材料所称76项测试当作本轮证据。本轮实际测试和例子见下方记录。

## 使用方式

```python
from cfm_id import project

# options 与原 inspect_methods 相同：已审核意图、实际事实回答、请求绑定及所需来源审核。
view = project.diagnose_methods(session, "q1", **options)
# 不调用 LLM，不执行数学求解，不产生批准。
```

已有原执行记录可以使用：

```python
from cfm_id.method_diagnostics import describe
view = describe(plan, plan_review=plan_review, native_reviews=native_reviews,
                result=execution_result)
```

未提交的审核显示待审；失效、错误作用域或错误审核权限显示 INVALID。跨计划、跨目标或证据不一致的成功记录拒绝展示为匹配证据。若同时提供审核和成功记录，须提供完整的共同及全部计划分支审核，且两者不能互相矛盾。整体阻断记录不能因残留成功标记而显示成功证据。不同模型版本的结果不能仅因目标指纹相同就合并。

七个离线示例可直接运行，输出目录应为新目录：

```powershell
python -m examples.method_diagnostics --allow-synthetic-reviews --output outputs/method_examples
```

| 示例 | 原执行结果 | 新诊断表达 |
|---|---|---|
| 两路线同时成立 | POINT，两个原生证书均重放 | R1b、R2各自报告成功，保留各自条件 |
| R1b零支持、R2成立 | POINT | R1b不适用，R2原证书重放成功；未启动PARTIAL |
| R2充分性未声明 | NEEDS_INPUT | R1b原生不适用；R2尚未进入计划，正支持未检查 |
| 有限完整模型 | PARTIAL，sharp `[13/28,15/28]` | sharp仅相对于当前已审核模型 |
| 模型完整性未确认 | NEEDS_INPUT，无后端调用 | 保留原生模型缺项及追问 |
| R2审核待定 | REVIEW_REQUIRED，无后端调用 | R1b已审，但现有全分支前置规则仍阻断执行 |
| 额外单调限制 | ADAPTER_NOT_CONNECTED，无后端调用 | 保留限制，不删除限制强行进入均值盒模型 |

这些示例使用已有固定业务和显式合成审核，是真实原生求解与重放，**不是新的 LLM 业务准确率成绩**。

## 两政策差值接入共同诊断

继续使用同一个`project.diagnose_methods`入口；家族由原业务入口和原生计划确定，用户不需要另选R1b、R2或PARTIAL。`catalog()`的默认行为仍为固定政策均值；`catalog(family)`仅投影指定家族在`capability_registry`中的既有方法，不新增可执行能力。

差值报告增加`comparison`，保留原生解析后的两端政策、评价名单和来源、`first_minus_second`方向，以及计划中的共同节点顺序、权重、结果和背景。未知方向或不同名单原样显示；不自动对齐，也不凭诊断补填。来源短别名仍按原解析器解析到材料坐标，不能要求它与原始短别名字符串相等。

| 方法 | 必须保留的检查 | 诊断如何表达 |
|---|---|---|
| R1b两端差值 | 两个完整政策各自的支持/A4、相同评价范围、端点与有向组合证书重放 | 分别保留`first`和`second`尝试；只成功一端不显示差值成功 |
| R2两端差值 | 共同科学模型、暴露与充分性，两端目标签名支持/A4，端点与组合重放 | 可同时显示R1b两端零支持和R2成功，不把路线失败变成非识别证明 |
| 有限模型联合差值 | 同一个完整信息与约束模型，直接对有向差值求界并重放 | 不要求两端单独点识别，不相减独立区间；差值可能因共享未知量抵消而成为POINT |

共同审核和每个方法的读取审核继续包含原生`PAIR_DECISIONS`中的方向、共同评价范围两项。科学审核、全部已计划分支的执行前检查、旧审核失效和合成研究范围不变。任何一端未准备好时，报告保留该端的原生缺项或排除原因；不猜测尚未声明的科学条件。

当前单方法端点执行记录不带`method`，多方法记录带`method`；联合求界没有单端`attempts`。`contrast_diagnostics`只适配这三种已有记录形式：两端不能合并丢失；方法归属不明确或端点重复的记录拒绝展示为匹配证据。成功记录还须与方向、共同范围、计划及对应证据内容一致。整体阻断、重放失败或不相容结果均不能显示证书成功。记录一致性检查**不是重新证明数学结论或认证任意外部JSON**，正式重放仍由原执行器完成。

九个可运行离线示例：

```powershell
python -m examples.contrast_method_diagnostics --allow-synthetic-reviews --output outputs/contrast_method_examples
```

包括R1b差值POINT、R1b不适用而R2成功、联合PARTIAL、共享项抵消后的POINT、反向比较、单端失败、第二政策漏读、名单误读和R2待审。漏读/误读作为显式测试故障单独标注，原业务材料保留；不是模型实际回答，也不是LLM准确率。

联合PARTIAL例的sharp界限为`[-1/2,1/2]`，相对于声明模型成立；本例等于其逻辑范围，不能说信息进一步缩小了区间。抵消例的差值为`1/5`，反向为`-1/5`；若相减两个单独识别区间，会得到更宽的`[-3/10,7/10]`，所以诊断必须保留“联合求界”的证据类型。

本阶段原始记录在`outputs/contrast_diagnostics_20261031/`。定向验收覆盖新诊断、原两政策执行、R2组合、共同政策入口、有限模型证书及能力登记；不与前阶段测试数累加，不改变原LLM准确率记录。

## R3观察性固定背景政策均值

当前也已登记`R3_MEAN_SIGNATURE`，由显式签名读取配置准备，详见[R3入口合同](R3_POLICY_ENTRY_CONTRACT_ZH.md)。其`signature_support`逐评价对象报告原证书中的签名及支持；`joint_policy_support`可以为0，两者不会混用。读取和科学审核增加独立的均值充分性范围项。旧Full计划仍按原合同执行，诊断中新增的签名项显示为未计划，不暗示已经调用或验证。下面保留Full阶段的验收记录，不将旧成绩算成新配置的验收。

公共入口不变，新增`observational`视图与`R3_FULL_ASSIGNMENT`记录适配。它只连接现有有限观察性入口，不代表全部原生R3目标已经接入；现有12节点枚举限额、简单固定处理前无向网络和合成研究审核限制继续保留。

| 要保留的含义 | 共同诊断中的对应内容 |
|---|---|
| 对所有对象指定的完整政策 | `declared_target.assignment`及`prepared_target.assignment`，不把评价子集当成完整研究名单 |
| 评价全体或指定子集 | 原名单及`unit_weights`，与完整政策分别保留 |
| 业务期间与固定处理前W | `business_context`和`fixed_conditioning`；原生目标同时绑定两者，不改成跨W平均 |
| A0与事实阶段的条件一致 | 原`target_conditioning_review`及工作表中的独立审核项；同样的文字也不自动批准；旧协议无此项时不伪造审核记录 |
| 条件交换性 | 原科学声明与审核状态分开；条件交换性不由观测概率或数据证明，也不替换为随机化 |
| 正支持和A4 | 原工作表检查完整表、条件均值范围及同一背景声明；是否有目标政策联合正支持只转述原执行记录 |

`joint_policy_support`在执行前为`NOT_CHECKED`。原R3成功并完成重放后才报告`NATIVE_POSITIVE_SUPPORT_REPORTED`及原证书的目标联合概率；原生报告零支持时显示`NATIVE_ZERO_SUPPORT_REPORTED`，不生成证书或非识别证明，不自动转均值签名、PARTIAL或LLM候选。正概率表已列全，也可能不包含目标政策；每个对象的边际采用概率均为正，仍不保证完整政策有支持。

改变固定背景、政策或评价范围须重新审核；原结果不能跨计划使用。证书与保存记录的目标、公式、支持摘要、输入身份和重放标记不一致时拒绝展示为已重放。诊断检查的是记录一致性，不替代原生验证器，也不认证任意外部JSON。

## 网络局部直接效应与同伴效应

继续使用同一公共入口`project.diagnose_methods`。这两种目标共用现有的`NETWORK_RANDOMIZED_EFFECT_FACTS`读取家族和`R1A_COMPOSITION`数学组合，但目标含义不同，诊断保留原文、审核后的类别和两端条件，不靠方法名称替用户选择效应。

| 项目 | 局部直接效应 | 同伴效应 |
|---|---|---|
| 比较什么 | 自身处理不同，同伴状态相同 | 自身处理相同，同伴状态不同 |
| 方向 | 例如自身启用减未启用，或反向；保留第一端减第二端 | 例如同伴高状态减低状态，或反向；不按状态大小重新排序 |
| 评价范围 | 全体、指定子集、单个对象分别保留 | 同左；不根据本次抽中名单生成评价对象 |
| 其余安排 | 在满足各端局部条件的完整安排中，按原设计条件概率平均 | 同左；两个条件对应的完整安排分布可能不同 |

这是**原设计条件平均的目标**，不是两份固定完整政策的差值，也不要求潜在结果均值只依赖局部暴露。原有枚举验收允许同一暴露组内的结果随完整安排变化，以检查目标没有被偷换成均值充分性目标。

新增`effect`视图保留原生解析的`declared_target`、带方向/名单/权重/设计/暴露的`ordered_target`和已有`target_kind_origin`。材料缺失或类别冲突时保留实际状态和来源，不补填目标。计数结果已有的“局部POINT均值”嵌入声明也原样保留，不推导连续分布或PARTIAL结论。

实际读取/科学审核项仍来自原生工作表，包括局部状态与方向、抽签前固定名单、原设计条件平均、变量含义和A4范围。D6额外的第一阶段排除条件，只在原生计划要求时显示，不把它变成所有设计的公共假设。D1–D6、E1–E5都仍须逐题通过原生支持与适用域检查；分类名称不能保证任何目标都有正支持。

执行证据有三个关键区别：

- `ANCHOR`只是一个初始局部状态的检查。它成功不代表全部评价对象、两端状态及完整效应都通过。
- `COMPOSITION`是原生命名直接／同伴效应组合；反向直接效应走已有`LINEAR_COMPOSITION`及其线性证书，不在显示层给原公式随意加负号。
- 新诊断核对阶段顺序、原输入记录、目标坐标、公式与证据摘要的一致性；不计算正支持、不生成公式、不重做数学证明。只有原执行记录报告完整重放成功，才显示`REPLAY_REPORTED`。

拒绝、待审、失效审核、缺失A4或平均规则继续阻断。初始状态成功但另一状态零支持、组合错误或重放失败，都不显示效应证书成功，不自动转PARTIAL或库外候选。改变方向、评价名单或设计后，原审核不能沿用。

十个离线示例可运行：

```powershell
python -m examples.effect_method_diagnostics --allow-synthetic-reviews --output outputs/effect_method_examples
```

示例保留完整合成业务原文，覆盖全体／子集／单个对象、反向直接效应、D6人数暴露，以及平均规则未声明、仅有限样本、分配后名单、零支持和待审核。零支持示例的读取故障明确标注；其他材料缺项例与其原文一致。它们使用手工读取和显式合成审核，原生求解/重放真实执行，**不作为LLM准确率**。
