## 本轮改动

- Schema 发布原解析器已经执行的状态、必填与类型规则，避免请求允许一种填法、本地又拒绝。
- Skill 只给出六步阅读方法：定位问题、确定减法方向、选择目标类型、区分目标字段、绑定原文、核对实际格式。
- 系统 Prompt 简短说明职责；格式示例给出真实赋值片段，避免把 `shape/choices` 等说明对象误当成业务输出。
- 只在确认来源目录完整覆盖原文时移除请求内重复展示的原文。规范来源、引用区间和原始材料不变。
- 背景、同伴条件及汇总方式的说明在请求、审核和重读中使用相同字段规则。

没有修改数学 Core，没有自动补齐模型答案，没有放宽科学审核或来源审核。

最终简短版有7份A0进入后续事实读取，均未通过完整审核：3份主要缺定义引用，3份混入其他问题的约定，1份新增未允许字段。没有进入数学 Core，没有产生本轮新 POINT 或重放成功记录。这不说明已有数学能力失效。

特别区分：

- 问“等待时间减少多少”却提交“使用减不用”，是改变目标的实质错误。
- 已正确列出六店，但本字段只引用“全部门店”而没有链接名单定义，是当前证据合同未闭合，不能直接断言模型算错或不理解名单。
- 已单列共同同伴条件，却还须在比较两端重复填写，是值得检查的接口负担；不能仅归因于模型能力。

## 工程验证与限制

初始接口修改的定向回归261项通过；最终简短候选的相关回归22项通过。两组有重叠，不相加。
较长步骤版曾完成wheel资源包含与独立导入检查；不是最终简短版的干净安装验收，也不是全仓库验收。
最终调用期间291份运行源码与冻结记录一致。

样本和审核属于开发诊断，不是独立盲评。主要使用JSON模式，不能因此假定供应商执行了完整Schema约束。Skill、Schema与请求呈现一起改变，不能归因于Skill单一因素。

本轮在这里停止Prompt迭代。保留短版作为候选；下一项更值得评估的是把对象定义、处理编码和共同条件显式绑定一次，再由后续字段引用已审核对象，减少重复生成。该建议尚未实施，不能用程序偷偷补来源后宣称模型成功。
