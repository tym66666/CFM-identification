# Prompt 与 Skill 的组织形式复核

后续实施已完成：组织实验与接口修复结果（历史实验记录不随发布分发）。新说明未显示稳定增益，因此不提升默认；本页以下保留调用前的设计判断与计划，不作为当前完成状态。

2026-10-30。基于当前源码、已保存请求、既有对照结果及下列一手资料。本页是设计评估，**没有修改当前 Prompt/Skill、模型参数或数学 Core，没有新 API 实验**。源码唯一维护位置仍为团队仓库 `research/identification/causal_idfm/`。

我的判断：当前职责边界值得保留，但组织形式还有改进空间。下一项应检验“更少的重复、更明确的字段归属、更易执行的工作步骤”，而不是给每个失败题增加一句防御性说明。改进能否提高准确率，尚须同条件对照，不能由文档形式推出。

## 实际核查

读取了项目 [Skill](../skills/causal-business-reading/SKILL.md)、[运行说明](../skills/causal-business-reading/references/runtime.md)、`compact_formulator`、`query_conditioning_contract`、`local_field_contract`、`local_role_ownership`、观察性事实 reader，以及上一轮保存的实际请求。

做得好的地方：用户无需先选定理；读取和科学批准分开；保留缺项与原文；首次、重读、审核共用部分字段定义；Skill 要求调用现有接口，不另建数学判断。Skill 主体已经较简洁，不能仅凭它没有带来增益就推断还需写更多规则。

值得改进的地方：

| 观察到的事实 | 含义与建议 |
|---|---|
| 上轮三门店 A0 的 system 为 4,649 字符、user 为 24,730 字符；对应 R3 事实请求为 1,303 与 11,758 字符 | 这是一个实际样本，计数为 Unicode 字符而非 token。需审查 Schema、示例、原文目录和说明的各自贡献，不能只压缩 system；也不能据长度断言当前错误的原因 |
| A0 同时含完整 sources 与来源目录；Schema 与系统说明都表达字段规则 | 一部分重复用于定位和完整性，不可机械删掉。可检验只向模型呈现一套完整、带结构的可引用材料，原文件及哈希仍由程序完整保存；表头、时点和定义关联不能丢 |
| 当前实验协议通过 `previous`、别名及文字替换继承旧说明 | 旧请求兼容有价值，但新推荐协议宜由单一字段合同生成。不要继续让历史说明层层决定新说明；旧协议保留原样 |
| 字段规则主要是说明和排除项 | 可增加少量与评测隔离的输入/输出对，例如“未知”与“明确未定”、名单定义与实际评价范围、资料说明与额外限制。示例须符合真实 Schema，不能只给模糊的理想答案 |
| 既有 Skill 对照只是附加文字，未实际调用其资源和接口 | 这测的是附加说明，不是工具辅助的完整 Skill。不能说已充分验证 Skill 的价值或无效性 |

既有同材料实验，首答完整链 LongCat 的 Prompt 与 Skill＋Prompt 均为 **1/4**，DeepSeek 均为 **0/2**。材料只有两个开发情境，次数很少；支持“尚未证明稳定增益”，不支持“Skill 一定有害或无用”。格式、语义、引用及后续筛选分母见原始对照记录（历史实验记录不随发布分发）。本次复核没有改写原始分数。

## 一手实践给出的方向

Anthropic 的 Skill 指南强调简洁、按任务脆弱程度约束自由度，并用示例和实际评测验证；这里可借鉴的是组织方法，不是照搬 Claude 的模型专属指令。对本项目，类型、来源编号和执行顺序适合由程序约束，业务含义仍需模型读取和独立审核。[官方编写指南](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)

Agent Skills 将说明、引用资源和可执行脚本组织在一起，按需加载。普通 Chat Completions 请求不会因为附加 `SKILL.md` 就自动获得文件读取或代码执行能力；这些能力需要宿主提供。这解释了为什么我们先前的文字附加实验不能代表完整 Skill 流程。[官方 Skill 设计说明](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)

上下文设计应关注每一步需要哪些信息，而非堆积所有规则。长上下文位置效应已有研究，但研究任务与当时模型不能直接代表今天的 LongCat/DeepSeek；它只提示我们应测材料顺序、表头距离及说明冗余，不能据此诊断本项目的根因。[Anthropic 上下文设计](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)、[Lost in the Middle](https://arxiv.org/abs/2307.03172)

DSPy 将调用组织成有明确输入输出的模块，再按指标优化；GEPA 利用执行反馈搜索提示词。值得借鉴的是固定接口、明确指标和有限搜索，不需要为本项目立即引入另一套大型框架或优化器。相关任务的收益不是我们的准确率保证。[DSPy 原论文](https://arxiv.org/abs/2310.03714)、[GEPA 原论文](https://arxiv.org/abs/2507.19457)

DeepSeek 官方 JSON Output 文档要求 JSON 模式、相应指令和合理输出长度；它描述的是合法 JSON 输出，不证明我们的字段、引用或科学语义正确。学校转发服务的具体约束支持须实际核验，不能假定等同官方服务。本轮没有新增兼容性请求。[DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode/)

## 建议采用的组织方式

| 层 | 放什么 | 不承担什么 |
|---|---|---|
| 短系统指令 | 当前任务、原文为资料、未知不猜、输出合同、不能批准科学条件 | 不复述每个字段的所有历史失败 |
| 唯一字段合同 | 名称、类型、含义、未知状态、所属阶段、引用依赖；生成 Schema、审核表及复查说明 | 不在三个地方各维护一份不同规则 |
| 本阶段工作说明 | A0 理解目标；网络或 DAG 的后续事实读取；按当前已审核结构加载必要说明 | 不让用户先选 R 类定理；不凭未经审核的路由丢掉其他问题 |
| 少量独立示例 | 正常、缺项、拒绝及引用依赖的完整输入/输出；用程序校验示例格式 | 不用待测题答案作为提示词，不用示例替代原文 |
| Skill 工作流 | 生成请求、接收原答、查看诊断、生成审核表、显式重读；资源按需读取 | 不自动批准审核，不代替数学证明，不默认无限重试 |
| 程序与数学层 | 类型/引用存在性/一致性检查、审核绑定、定理应用、证书重放 | 不靠字符串猜业务意图，也不自动补足引用蕴含关系 |

接口已经具备不少上述能力，下一步应复用它们。先做保持输入输出合同不变的请求组织实验；若之后需要改变 wire 字段，再单列协议迁移与兼容验收。不能把格式调整、增加调用次数和换模型同时进行后，笼统归功于 Skill。

对于当前网络干扰主线，A0 保持足够广泛，完整保留所有问题及不确定结构；后续按已审核结构选 reader。按需加载应减少不相关说明，而不是仅因材料中出现“门店”就隐藏 DAG，或为了适配已有定理删除限制。

科学边界不得作为优化参数。合法枚举、绑定、字段完整性可以程序检查；来源是否蕴含整条主张仍需独立审查。模型自查可辅助找错，但不能成为科学批准。原文没有的信息仍不得由示例、Skill 或工具替它补齐。

## 一个有限的验证方案

先做两组：当前冻结请求，和同 Schema、同字段定义下整理后的请求。不同时改业务题、审核口径、模型参数或可调用数学能力；原始材料保持完整。若还要测试工具辅助 Skill，作为后续单独的一组，并另计工具调用与耗时。

用新的完整业务做小规模诊断：两个独立情境，各一个正例和一个缺项/拒绝负例；两模型、每配置重复两次。A0 共32次，只有严格通过的回答才进入事实阶段，事实最多32次；这是初步筛选预算，尚未安排调用，也不够证明广泛泛化。诊断样本不能再当最终留出验收；有收益后再冻结更多未参与开发的业务。

提前固定每题目标、两端、名单、信息范围、条件和引用判据，保留格式、语义、引用、最终预期分支四类分数。首答与重读分开；没有通过首阶段的题仍在整链原始分母。正确业务含义与严格协议符合性分别报告，不能以格式失败冒充数学失败，也不能事后取消失败规则美化分数。

硬门槛仍是缺项/拒绝不被错误送入已认证结果、原有证书链不被绕过。成本、延迟、人工复核量作为次要指标。两次有明确假设的设计迭代若仍无稳定收益，应停止扩写提示词，保留受审核主线及失败记录；更换模型或训练属于下一项独立决策。

这与 Agent Skills 的基线对照、真实场景和边界例评测方向一致；本项目额外要求在调用前冻结关键判据，避免看到输出后补条件或改分母。[Agent Skills 评测指南](https://agentskills.io/skill-creation/evaluating-skills)
