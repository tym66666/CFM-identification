# 比较两端、评价名单和背景：引用改进与新业务重复验收

后续的 A4 范围修改及新一轮冻结正负例见[A4 范围验收](NETWORK_EFFECT_A4_SCOPE_ZH.md)。下面保留本批原结果与失败，不用后续复查覆盖首答。

2026-10-28。本批只在本地修改读取请求、公开 Schema 的展示顺序和测试材料；数学 Core、适配器的准入条件、求解器、独立验证器及 Estimation/Policy 未改，没有提交或推送。前一批失败保留在[来源覆盖验收](NETWORK_EFFECT_SOURCE_COVERAGE_ZH.md)。

## 修改与理由

前版正文说 `target.source_ids` 覆盖比较目的和方向，但 Schema 责任表还要求覆盖评价名单与汇总方式。现将两处说明统一，明确父记录也要引用名单和平均方式，不能借子记录的引用代替。

两端引用分别支持用户指定的自身状态和同伴状态。只介绍工具、0/1 编码或分组定义，不能说明用户究竟要比较哪一端；必要时需引用比较问题和编码定义。背景引用则按该记录实际写出的主张覆盖；若背景复述了两端共同期间、背景或结果口径，就要有这些声明的原文支持。

`source_coverage_contract.py` 还将公开 Schema 每个对象的 `properties` 调整为事实字段在前、引用数组在后，建议模型完成事实后再列来源。该调整不增加回答字段，不改变类型、必填约束和解析器；实际回答的 JSON 顺序不是准入要求，也不会被程序重排修复。请求元数据为 `field-local-citations-2`，回答协议与历史证书协议不变。旧请求和旧审核仍须失效。

这是面向字段职责的说明，不含题号、业务名称、预期公式或标准答案。原审核门槛未放宽，也没有自动补引用、填格子、删除额外限制或批准科学条件。

## 冻结设计与实际调用

共调用 **20 次 LongCat-2.5-Preview**，均返回完整 JSON；关闭思考模式，300 秒请求上限。6 次为三个已知材料的新旧说明对照，14 次为 7 份新材料各读两次。事先冻结 Prompt、材料、源码摘要与评分口径；不根据返回内容临时改题、改 Prompt、反复请求直到通过。无重试、无显式重读，原始回答未修改。

新材料来自三个业务情境：家电维修点调借备件、社区生鲜门店调货、图书分馆馆际预约。使用完整自然语言问题及配套研究材料，明确对象、网络、抽签、可用总体信息和拟采用的科学条件。覆盖五节点链、四节点环、六节点的两个互不相连三角形；评价全体、固定两对象、单对象。合并重排版本与同题重复不算独立业务。

全部材料的 A0 为公开披露的人工参考。参考答案没有发送给模型，因此本批测量**事实读取阶段**，不能当成新的完整 LLM 端到端准确率、NBIB 总体成绩或独立盲评。审核由开发助手对照原文完成；科学许可仅为 `SYNTHETIC_TEST`，不代表真实企业条件成立。

## 结果：引用问题与信息遗漏分开

| 新材料（各重复两次） | 两端／名单／背景引用通过 | 整份事实严格通过 | 实际分支 |
|---|---:|---:|---|
| 家电维修，全部五点，分文件 | 2/2 | 2/2 | 两次 POINT、独立重放 |
| 同一维修业务，合并重排材料 | 2/2 | 2/2 | 两次 POINT、独立重放 |
| 生鲜调拨，固定两个门店等权平均 | 2/2 | 2/2 | 两次 POINT、独立重放 |
| 馆际预约，只评价一个分馆 | 2/2 | 2/2 | 两次 POINT、独立重放 |
| 维修，两端共同背景尚未确认 | 2/2 | 1/2 | 两次 NEEDS_INPUT；一次漏了部分已声明总体信息格子 |
| 生鲜，随机分配与潜在结果独立尚未决定采用 | 2/2 | 2/2 | 两次保留 UNDECIDED，NEEDS_INPUT |
| 馆际预约，另加逐对象逐完整安排的均值上界 | 2/2 | 0/2 | 两次保留真实上界，ADAPTER_NOT_CONNECTED；均遗漏总体信息格子 |
| 合计 | **14/14** | **11/14** | **正例 8/8 POINT 并重放；负例 6/6 不调用后端** |

三个未严格通过的首答必须保留：

- `library_extra_1`、`library_extra_2`：材料声明六个分馆各四个状态的总体均值可用，模型正确保留对象范围、符号总体信息及均值不超过 12 天的额外条件，但 `arm_cells=[]`。两份都不能算完整读取正确。
- `service_context_pending_2`：模型正确保留共同背景未确认，却只列了本次目标使用的 10 个格子；材料实际提供五个对象全部四状态、共 20 个格子。遗漏了同伴低状态下的另外 10 个格子。

这三份没有进入求解，也未获得读取或科学批准。不能因为负例安全阻断就抹掉信息读取缺陷。特别是：**“材料提供什么信息”不能缩成“当前目标需要什么信息”**；存在未定条件或额外限制也不允许提前停止读取其余材料。

同口径的旧题对照，新旧说明均 **3/3** 严格通过。旧方案在上一批出现过漏引，本次又通过，说明模型存在波动；小样本没有证明新说明具有普遍或统计显著的优势。输出顺序也未被模型稳定遵循，不能把本批成绩归因于键的排列顺序。

对真实回答，审核依据其实际主张和原文语义，而不是要求与人工参考的引用列表逐字相同。只复述业务简介的背景可以只引简介；一旦写入两端共同比较条件，就须相应原文。相关辅助来源可以重复引用，但不能粘贴全目录。三项引用通过并不替代总体信息完整性和其他科学条件审核。

## 程序与数学边界验收

- 最终定向测试 **110 passed**，包括新增 12 项。首次新测试误将“JSON 主体加后续说明”的请求文本当成单一 JSON 文档，出现 8 个测试辅助代码错误；修正为只解析 Schema 所在主体后，完整定向重跑通过，未改变运行解析器。
- 完整固定框架实际 **1406 passed、133 个 subtests passed**，耗时 637.12 秒，无缺失必需节点，运行期间源码不变。定向与全量有重叠，不累计。
- 新测试分别模拟比较第一端、第二端、名单、背景引用不足；即使编号存在、坐标正确，独立来源审核拒绝后仍不进入数学编译。JSON 键顺序变化不改变解析结果。
- 历史 14 个政策均值、两政策差值、PARTIAL 与 DAG 固定案例的请求、计划、审核和结果不变；历史研究目录和会话列表不变。
- 离线构建并安装 wheel，源码外 7 个新旧入口正负例符合预期，206 个加载的项目模块全部来自安装目录。
- 新材料 8 个正例及新说明下两个已知正例均实际通过原生独立证书重放；另枚举 16、32 或 64 个完整安排，核对概率、带符号系数及目标值。枚举允许同暴露组内的潜在结果变化，没有偷偷加入暴露充分性，也不是业务效果估计。

运行代码相对本批开始只改了 `network_effect_reading.py` 和 `source_coverage_contract.py`。原始模型输出、请求、审核及证书保存在代码仓库外 `LOCAL_EVIDENCE_NOT_DISTRIBUTED`，不作为源码提交材料。认证文件仅由请求进程载入，密钥没有输出或记录。本批结束 LongCat 余额 **53 次**；DeepSeek 未调用。

本轮三类引用漏填在新样本中未复现，但不能据此称系统已普遍稳定。下一步优先解决**负例中仍须完整读取 A4 范围**的问题，并同时保留“只提供部分格子”的负向对照，避免程序或模型自动补出不存在的信息。暂不扩大数学路线。
