# 从业务问题开始的入口

用户只需提出业务问题、提供材料，并回答与实际业务有关的澄清。用户不需要选择 `lane`、R1a/R1b、后门/前门或 POINT/PARTIAL。

开发者现在可通过 `ReadingConfig` / `start_configured` 或 CLI `--reading-config` 集中设置读取格式与说明；旧调用接口和检查点保留。具体组合、审核失效规则及扩展接点见[开发端读取配置](BUSINESS_READING_CONFIG_ZH.md)。这些不是用户需要选择的识别路线。

先前九种 `research_session` 配置是专门读取器及审核链的开发接口。把它们当作真实用户的第一步会倒置流程。现在 `cfm_id.business_intake` 是无路线选择的读取会话起点，新会话复用精简多目标读取及原文编号，再投影到已有 A0 Schema 和来源审查。

## 当前实现与尚未完成的连接

```text
业务问题及材料
    ↓ 已实现：business_intake，创建时不选方法
A0 读取：多个目标、研究对象、结构、业务口径；原始材料完整保留
    ↔ 已实现：业务澄清、原文补充、重新读取、保存与恢复
选定子问题的独立意图审核
    ↓ 已连接首个范围：变量 DAG 事实读取及原生问题投影
原生读取/科学审核与完整分派计划审核
    ↓ 已连接：同一模型的后门、调整、前门方法检查
数学后端 → 独立验证 → 识别结果
```

**已接通变量 DAG 的首个有限闭环，见 [业务分派接口](BUSINESS_DISPATCH_ZH.md)。** 业务读取层自身的 `SEMANTIC_REVIEW_REQUIRED` 仍只表示已有可供审核的读取稿，`method_matching=NOT_PERFORMED` 表示尚未在此阶段检查数学方法。随后由独立分派调用检查；不能称为“任意业务自动分派已完成”。

网络中的固定政策均值已接通 [共同事实读取及 R1b/R2 检查](NETWORK_POLICY_DISPATCH_ZH.md)，支持的原设计、总体信息与科学条件须逐项审核。[两个固定政策的有向差值](NETWORK_CONTRAST_DISPATCH_ZH.md)也已连接已有R1b组合与D2/E1联合有限界，保留合成研究限制和完整共同模型审核。网络其他目标及未连接结构继续保留原生路线，分派桥明确返回尚未连接，不把路线选择题推回普通业务用户，也不称为数学不可识别。

新会话的后续事实读取默认使用短来源编号（`fact_format='short_refs'`），长来源哈希由程序保管。历史检查点缺少该字段时仍使用旧长编号协议。`configure_fact_format` 可显式切换读取协议，保留原 A0 和材料但使后续审核绑定变化；它不修补旧模型回答。多子问题整题验收见分派接口的 `business_case`，不会用 q1 成功代表整题完成。

## 分类应放在哪里

| 层次 | 记录什么 | 何时使用 |
|---|---|---|
| 目标 | 比较什么、谁的结果、时间、完整政策或局部暴露、聚合方式 | A0 读取与 A1 意图审核；每个子问题独立保留 |
| 研究结构 | 单位间关系网络、变量因果图、处理与结果类型、时间结构 | A2/A3；两种图可能同时存在，不强制互斥 |
| 可用信息 | 分配律、总体分布或总体均值、实际只有样本的信息 | A4；设计类型和信息类型分别记录 |
| 科学限制 | 随机化、一致性、交换性、暴露均值充分性、界限、均值顺序等 | A5；只有来源声明还不等于独立批准 |
| 方法 | 原 Core 的 R1a/R1b/R2/R3、DAG 调整/前门、有限模型求界等 | 在目标、信息和审核明确后检查适用性；可有多个候选 |
| 结果 | 可观测公式、识别区间、sharp 性质、反例或缺少条件 | 实际计算和验证后产生；不要求用户预选 |

这是一组不同的分类维度，不能拼成一个扁平业务菜单。R1a/R1b/R2/R3 是项目内的数学方法分组，不是网络拓扑种类。九种现有配置也不是理论上必须分成的九类问题。

## 方法匹配合同

当前 DAG 连接及后续扩展须遵循以下规则：

1. 每个子问题先绑定审核后的目标、资料和模型条件；LLM 读取稿只供建议，不能直接授予原生许可证。
2. 候选方法分别返回适用、条件未定或超出支持域及原因。来源字符串、LLM 输出的方法名、参考答案均不能成为适用性证明。
3. 一个目标允许多个候选方法；按它们真实的数学前提检查。固定政策目标不应因可能得到区间而被改写成另一个目标。
4. 不补造总体信息、界限或单调性，不静默丢弃已知约束后声称 sharp。任何模型变更均成为可见、独立审核的条件版本。
5. 未找到当前可用方法不等于已证明不可识别；复杂 DAG、动态网络、IV 或混合结构须保留原意并说明当前覆盖缺口。
6. 原生准入、证书和独立重放继续保持；接入层只组织流程，不改数学 Core。

## 本地使用

在源码目录执行，输出使用新文件：

```powershell
python -m cfm_id.business_intake_cli new --question-file business_question.txt --output outputs/intake_01.json
python -m cfm_id.business_intake_cli request --intake outputs/intake_01.json --output outputs/request_01.json
```

有附件时，使用 `--case-json` 提供现有 `BusinessCase` 格式：`case_id, business_question, sources, response_language`。附件解析继续复用 `cfm_id_llm.material_integrity.create_grounded_intake`；该 CLI 不新增文件解析器。

新请求复用 `cfm_id_llm.compact_formulator`：模型每个目标只写一次，并选择当前材料的原文编号；程序生成目标编号、共享 target 和精确引文。业务含义仍由模型提出，绑定引文不证明语义正确。对象网络与变量因果图分别保留；历史分配与目标干预也分别处理。A4/A5 由后续专门读取及审核处理，初步读取不授予科学许可。

仅 `system_prompt` 与 `user_prompt` 交给 Provider；请求摘要留在本地绑定回答。已有已授权 Provider 可在 Python 中调用一次 `business_intake.read_once(intake, provider)`。CLI 默认不联网，也不读取密钥。`inspect` 只在本地验证、投影，不再调用 LLM；原始模型 JSON 保存在 `candidate`，投影及缺项检查分别放在 `report` 和 `wire_gate`。

精简格式的缺项及格式/矛盾复查信号同样阻断分派，不能只看投影后的旧 A0 审查而漏掉这些信号。有来源的 `INTERPRETED` 表述保留为解释，进入独立意图与来源蕴含审核；它既不自动获准，也不因其标签而永远要求模型重新生成。缺项追问先核对原文，避免把模型漏读误认为用户没有说明。

历史检查点缺少 `reading_format` 时仍按 `canonical` 及原 `quality_prompts` 读取；兼容调用可显式 `start(case, reading_format='canonical')`。这是内部读取协议兼容选项，不是要求用户选择因果路线。不同格式不自动猜测或相互修复。新旧记录及所有审核仍绑定其实际材料、请求和候选；已有分派审核若绑定摘要变化需重新审核。

读取 Prompt 的实质性变更也会改变请求绑定。旧 compact 检查点不能被悄悄当作新 Prompt 的回答继续执行；应保留当时的请求和原始回答用于追溯，在当前协议下重新读取、审核。当前提示明确区分“用户所求的均值”与“材料提供的分布”，也区分“潜在结果均值的科学限制”与“变量间因果箭头”，避免因此改变目标或混淆两种图。

```powershell
python -m cfm_id.business_intake_cli candidate --intake outputs/intake_01.json --request outputs/request_01.json --candidate actual_reply.json --output outputs/intake_02.json
python -m cfm_id.business_intake_cli inspect --intake outputs/intake_02.json --output outputs/reading_review.json
python -m cfm_id.business_intake_cli plan --intake outputs/intake_02.json --output outputs/questions.json
```

`reply` 用当前问题编号和纯文本答复追加材料；`revise` 显式修订材料。两者清除旧候选，重新生成请求绑定；旧请求回答不能用于新材料。澄清计划也绑定当前候选，不能在候选替换后继续沿用。

用户答复单独进入可引用来源；助手之前提出的问题及目标概括只放在明确标注的澄清上下文中，不成为用户事实来源。补充后的请求保留这段上下文以理解简短答复。重新整理材料时清除旧澄清上下文，避免默默改变答复归属。摘要用于内容绑定，不是身份认证或真实性证明。

来源引用检查只证明引文确实存在，不证明解释正确。A0 的多目标上限、字段表达能力和语义误读风险仍存在，须另用独立冻结业务材料测量，不能拿这里的 Mock 结果当模型准确率。

## 单个对象与汇总口径的可选说明

### 单个方案水平与两个方案差值

`target_summary_contract='target-summary-3'` 在已有目标量/缺项说明上，补充“单方案水平、两个完整方案的有向差值、分别要求两个水平”的区别。它仍是开发端可选实验说明，未成为默认。旧说明、旧请求、旧审核绑定和解析规则保留；不会按业务关键词改写模型类别，也不自动补基准或批准科学条件。

对象网络中，明确的一份安排下的均值使用既有FIXED_POLICY_VALUE；两份完整安排的均值差使用既有粗粒度TOTAL_EFFECT。方向、评价人群和安排须保留在原目标中，并由后续专门读取及独立审核确定；“下降多少”不能机械当成新减旧。明确要比较但基准尚未决定时，类别可保留差值，comparator仍为UNKNOWN。两份历史/备选安排不等于用户请求比较它们，分别问两个水平也不等于另问差值。

测试材料见 [8条业务描述及独立参考标签](../evaluation/business_target_reading_cases.json)。例如销售团队的问题写成“如果从第二种安排改为第一种安排，四个小组平均每组一周的销售额会增加多少”，配以协作关系和已有记录；不要求业务人员提供识别路线名称、规范化JSON或数学术语。参考标签只供评分，不发送给模型。

这组材料刻意只有日常有限记录，没有额外声称总体信息或因果假设，因此用于检验业务读取，不能把读对目标当成已经识别。用于数学证明验收的严格合成模型另行保留，两类测试不能混报。

`target_summary_contract='target-summary-1'` 仅补充 A0 的目标字段解释：`target_population` 表示评价谁，`aggregation` 表示所求结果量及其概括方式。明确问单个对象的均值、期望或事件概率也是完整的目标口径，不需要为了填字段另造跨对象权重。若概率事件对应原文明示的二元结果指标，可将其解释为该指标的均值，并按来源支持的解释独立审核。其他事件不能默默替换成已有结果变量的均值。

```python
from cfm_id import business_intake

session = business_intake.start(original_case, target_summary_contract='target-summary-1')
```

这是开发端实验配置，不要求业务用户选择类别或识别路线。实现位于 `cfm_id_llm/target_summary_contract.py`，只增加 System Prompt 说明及已有 aggregation 字段的描述，没有增加候选字段、自动填值、语义分类器或科学许可。默认 None 保留旧请求；配置保存在会话中并参与请求绑定。不得给旧检查点直接加字段冒充新配置下的回答；重新建立读取、提交实际返回并审核。规范格式 canonical 不使用此精简读取说明。

全部对象的处理安排与评价人群分开：即使只评价一个对象，政策仍可能是全员启用。多个对象只有在原文明确时才能填写等权或其他权重；明确尚未决定目标量时仍为 UNKNOWN。原始候选若漏填 aggregation，程序保持阻断，不会因为只出现一个对象名称而补均值或权重1。原文重读保留这一配置，候选变化仍需完整审核。

回归合同在 `tests_gateway/test_target_summary_contract.py`，框架清单 S23 验证旧绑定、缺项阻断、独立审核与重读变化审核。真实模型试验与测试夹具分开记录，不能由离线通过推定 Prompt 准确率。

2026-10-27 冻结验收：36项定向测试、完整框架632个测试及125个子测试通过，7份历史请求不变。真实模型共12次调用（9次A0、3次事实读取）：6份明确目标的汇总口径正确；3份未定负例中2份保持UNKNOWN，另一份把未定说明写成STATED值，由独立目标与来源审核拒绝。三条实际正例经独立审核后完成R2 POINT及重放。另保留目标暴露推算、A4/A5字段混写和NOT_APPLICABLE标签问题，不将目标字段8/9称为整份读取或一般准确率，配置仍为可选。报告在源码包外 `LOCAL_EVIDENCE_NOT_DISTRIBUTED`。

### 已知“尚未决定”不等于目标值已经确定

后续实验配置 `target_summary_contract='target-summary-2'` 保留前述单对象说明，并进一步区分来源陈述和已定目标坐标。原文明示尚未决定均值、总和或必要权重时，相关字段仍为 UNKNOWN；goal 保留已定部分及未定原因。政策、评价对象已定时继续保留，不清空整个目标。明确“不取平均，取总和”或“此前未定，现在已明确”应保留现在的确定口径；不知道答案数值或能否识别也不等于目标未知。

```python
session = business_intake.start(original_case, target_summary_contract='target-summary-2')
```

这是开发端可选配置，默认及 target-summary-1 的实际请求保持不变；不要求用户挑选协议。它只改变说明文字和已有字段描述，不增加字段或关键词修补器。模型若仍把“尚未决定”写进 STATED 值，程序不会替它改写，独立来源审核须拒绝。总量读对也不表示已获现有均值适配器支持。

新增测试 `tests_gateway/test_target_readiness_contract.py` 归入 S24；38项定向测试与完整框架639项测试、125项子测试通过（两批重叠，不相加），16份历史请求复核不变。未决 kind 当前可能进入 READING_RECHECK_REQUIRED，而权重缺失可进入 NEEDS_INPUT；前者不自动证明模型误读，仍须结合原文判定，并保持无后续事实或数学调用。这一状态表达问题尚未修改。

冻结真实验收共17次调用：六题、两个模型各一轮并各重复一次原失败题，14次A0尝试中13份返回，1次LongCat传输失败。13份返回的汇总口径状态及含义正确，8次未定目标均阻断；DeepSeek一处比较对象标签仍不合规，LongCat重复题类别仍不稳定。三个实际后续事实读取均经独立合成审核完成R2 POINT、独立重放和整题汇总；第四个计划正例因首读传输失败未继续。总量只检查原意读取，未宣称已获均值适配支持。报告在源码包外 `LOCAL_EVIDENCE_NOT_DISTRIBUTED`；这些是窄字段及特定链路结果，不是整体模型准确率，未升级默认。

后续已接入[停止原因的来源审核](READING_REVIEW_GUARDS_ZH.md#先判断为什么停下用户缺项还是读取错误)：原文确认缺项后可明确转为目标补充，原文漏读或协议冲突则留在读取复查，所有结果仍阻断事实请求和数学调用。这是可选的本地审核记录，不修改Prompt或原始候选。重新使用上述8份真实负例返回验收，7份经独立来源审核停在NEEDS_INPUT，1份带非法比较标签的仍需重读；已有3条POINT链路重新计算和独立重放通过。没有新增API请求，也不将这些复验重复计入模型准确率。

### 来源编号的可选传输格式

可在创建会话时设置 `a0_reference_contract='compact-source-selectors-1'`，使A0选择 `s0001` 等短编号，并在顶层返回一次本轮 `reference_context`。此项与目标语义合同独立，用户仍只提交业务问题；开发端配置引用编码，不选择识别路线。默认长编号及历史检查点不变。材料、会话、补充答复和显式重读仍有独立绑定，无效引用不纠错，科学假设不自动接受。详细边界及CLI见[审核边界说明](READING_REVIEW_GUARDS_ZH.md#可选的-a0-短来源选择编号)。

另外可设置 `a0_response_contract='explicit-sections-1'`，要求明确返回共有事实与每题目标区域，避免整段省略被默认值掩盖。未知字段仍可保持未知，区域返回也不替代业务与科学审核。此项与来源编号独立，旧配置保持原样，见[响应区域的边界](READING_REVIEW_GUARDS_ZH.md#可选的-a0-响应区域完整性)。

字段解释、缺项状态与证据审核已整理为[共享字段定义与逐项审核](BUSINESS_FIELD_CONTRACT_ZH.md)。新审核接口逐项记录字段职责、值状态和本字段引用是否覆盖完整表述，再接回现有query review；它不改变Prompt、不自动补值，也不增加业务用户要选择的路线。已有审核入口继续兼容。
