# 读取工作流、单一政策交接与冻结验收

2026-11-01，本地修改。原工作源码目录继续作为唯一维护位置；未同步发布目录、未提交或推送。数学 Core、科学审核和独立证书验证保持不变。

**结论：候选没有显示首读增益，不替换推荐配置。本轮停止继续调 Prompt。** 接口上的明确改进与模型实际准确性分开记录。

## 本轮具体改动

- `cfm_id_llm/guided_policy_reading.py`：显式实验配置，复用已有单一主政策、精确别名兼容、解析、字段审核及重读。主政策由 `intervention` 持有；存在兼容别名时仍须同状态、同文本、同引用集合，不做语义猜测或合并来源。
- `cfm_id_llm/resources/business_reading_workflow.md`：共享读取步骤，由请求生成器加载，项目 Skill 引用同一份内容，不再额外维护第二套格式。该文件不包含测试题、参考答案或科学批准。
- `compact_response_contract.policy_focus_readers` 与 `business_dispatch`：由合同声明哪些事实读取家族接收单份已审核政策。候选覆盖固定政策均值、两政策差值和 R3；旧配置保持原有请求和范围。R3 的固定背景仍独立绑定、审核。
- 真实调用全部结束后，仅补齐候选的背景 Schema：`UNKNOWN` 不得携带值或非空引用，已知状态须有非空内容和引用，引用不得重复。解析器原已执行这些限制；修复是把限制提前展示给模型，没有放宽解析、删除原答引用或补答案。旧协议未改。

后一点源于本轮 LongCat 的真实回答：`conditioning_context={"state":"UNKNOWN","value":null,"refs":["s0002"]}` 能通过原 Schema，却被本地解析拒绝。这是接口合同差异，不能全归因于模型能力。候选修复后只有离线验收，**未做新的真实 LLM 测试，原成绩不重算**。

## 对照方法

四份新材料来自三个独立合成情境：维修点固定政策均值、中央厨房两政策差值 PARTIAL、冷链库 R3 正例，以及同一冷链库仅将交换性改为尚未决定的负例。每题包含完整业务问题及配套研究材料。正例中的科学条件和总体信息是合成研究预先声明，不代表真实企业自然拥有这些信息。

先用私有手写参考检查数学可执行性，分别得到 POINT、PARTIAL、POINT、NEEDS_INPUT；三个数学结果均独立重放通过。这不是模型成绩。厨房总体表在首次调用前补足了已有编码和结果定义的表头，以符合现有有限信息单来源表合同；原准备记录保留。API 开始后材料、运行源码和参考均未变化。

基线为推荐的 `query-conditioning-1`；候选为 `guided-policy-reading-1`。两臂使用相同材料及后续事实配置，R3 显式采用 `mean-signature-definitions`。每模型各读取四题、两臂交错顺序。只有候选继续事实读取；每条候选链至多一次显式复查，不自动重试，不看回答补条件，不修写模型 JSON。基线后续链路未测，不能写成失败或与候选比较全链路准确率。

这是“工作流说明＋单一政策合同＋R3交接”的组合对照，不能单独归因于 Skill。远端模型只接收保存的请求，没有文件工具或自主执行 Skill 的宿主。系统说明虽从 4,957 缩至 1,141 字符，但第一题完整请求从 27,497 增至 28,933 字符，原因是沿用的分支 Schema 增大；不能声称整体提示更短。

## 已确认与未解决的边界

1. 程序连接：候选 R3 单份政策交接、固定背景保留、缺项、拒绝、旧批准失效及重放已做离线验收。已有能力继续复用原数学入口。
2. 明确接口差异：候选背景 Schema 已补齐，解析器保持严格。旧协议为兼容保留原请求，包括其历史 Schema 表达限制。
3. 仍存在模型读取问题：总体量填进样本、普通研究背景填成目标条件、向量或名称漏引定义、误加具体日期；候选重排说明没有解决它们。
4. 兼容负担：候选虽要求单一主政策，Schema 仍展示可选兼容字段和其他目标分支，模型仍会重复填写。此次只证明这是实际失败点，不能证明去掉某一句提示就一定改善。

后续若继续优化，先把旧客户端兼容视图与发给模型的最小字段视图区分清楚，并保持科学审核和原答不变；先检查合同一致性，再做有限留出测试。不要把整个数学扩展工作都卡在这项读取实验上，也不将候选提升为默认。
