## 明确定位的工程问题

七份实际事实回答（含复查）都出现如下组合：

```json
{
  "status": "NOT_STATED",
  "source_ids": [],
  "scope": "UNKNOWN",
  "covered_nodes": [],
  "definition_refs": ["study"]
}
```

它们正确保留了“没有声明均值充分性”，但又给这条没有直接主张的记录附上定义依赖。现有解析器要求使用定义依赖时有直接主张来源，所以拒绝；独立字段 Schema 校验此前通过，错误诊断没有定位这个组合。这是**字段组合与诊断覆盖不齐**，不能全算成业务语义能力问题。

API 全部结束后，本轮只给 `wire_type_diagnostics.py` 补上既有规则的定位：`/mean_sufficiency → DIRECT_CLAIM_SOURCE_REQUIRED`。新的显式格式复查可以携带现有规则。没有改请求、Schema、Prompt、解析器接受范围或数学输入；没有自动删掉依赖，也没有为 NOT_STATED 凭空补来源或许可。

这项诊断修复经过离线验收，**没有再调用 LLM 测效果**。七份原答的拒绝结果不变，冻结统计不变。此前本地复查准备器误将尚未被类型诊断覆盖的问题标为 WIRE_FORMAT_ERROR，被预检挡住；两个无效草稿保留为 `invalid_preflight`，在发送前改为原有 UNSUPPORTED_ADDITION 定位，未消耗调用次数、未加入替换答案。

下一项工程工作应让公开 Schema、解析规则、来源审核和诊断同时表达这条组合约束，并明确旧会话兼容方式；不应继续堆业务提示语，更不能把未声明的科学条件默认接受。由于本轮冻结验收未通过，当前推荐配置保持原样。
