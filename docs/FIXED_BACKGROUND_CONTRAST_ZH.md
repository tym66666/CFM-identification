# 固定背景的两政策目标：入口交接合同

2026-11-01，本地修改。正式推荐读取配置、模型 Prompt、数学 Core 均不改变。

## 为什么以前停在入口

数学层早已把研究背景放在 `study.context_reference`，目标、A4 来源和证书均绑定它；R2 的均值充分性、有限有界模型和均值顺序模型也都是给定该背景的命题。但 A0 后来增加逐问 `conditioning_context` 时，只有 R3 配套了跨阶段交接。其他读取器遇到明确背景会返回 `CONDITIONED_TARGET_NOT_CONNECTED_TO_SELECTED_READER`，以免旧投影丢掉条件。

本轮接通的是**已有随机化网络两政策差值**，不是新增观察性差值定理，也不把所有带条件的问题都放行。

## 含义与审核如何衔接

目标为同一评价集合、同一背景下的有向差值：

\[
\Delta(w)=\sum_{i\in S}\omega_i\bigl\{E[Y_i(z^A)\mid W=w]-E[Y_i(z^B)\mid W=w]\bigr\}.
\]

当前共同入口仍采用原有等权评价合同。第一端减第二端，评价名单、时期、结果定义和背景都要一致。

| 位置 | 职责 |
|---|---|
| A0 `conditioning_context` | 保留用户明确限定的条件及来源；采用支持此字段的现有显式协议 |
| 事实 `study.context` / `study.source_ids` | 保留实际研究时期和固定背景及引用；不增加第二个重复背景字段 |
| `fixed_conditioning_matches_reviewed_query` | 独立核对两个阶段含义一致；字符串相等也不能自动通过 |
| 新增四项科学审核 | 确认处理前同一背景和总体、该背景下的完整分配律及随机化、该背景下的 A4、该背景下的全部科学限制 |
| 原生编译和重放 | 原样使用事实中的背景，同时绑定两端目标和信息；既有联合模型、支持检查和证书不变 |

四项审核的完整中文说明由 `cfm_id/network_contrast_context.py` 统一提供，显示在计划的 `target_conditioning_review.scientific_requirements`。每一项都进入现有科学审核工作表，待定、拒绝、遗漏、过期均不能执行。审核只能确认材料和明确声明的研究前提；材料缺条件时应补问，不能把勾选当作自动新增科学事实。

尤其不能从无条件随机化推出任意条件下的随机化。原数学合同需要的是

\[
T\perp\{Y_i(z):i,z\}\mid W=w,
\qquad q_w(z)=P(T=z\mid W=w).
\]

例如使用 R2 时，还需要独立审核全安排的均值充分性，并检查目标签名的正支持。此时

\[
E[Y_i(z)\mid w]
=E[Y_i^{obs}\mid s_i(T)=s_i(z),w]
\]

才有依据。有限 PARTIAL 的 A4 均值、科学界限、均值顺序及模型完整性声明，也必须属于这个相同背景。具体证明继续使用 [有界模型数学合同](BOUNDED_POLICY_MATH_ZH.md)及既有均值顺序实现；本轮没有修改证明或求界算法。

## 保留的边界

- “同一周”或“两端背景一样”不等于已说明用户指定的背景；背景引用和语义仍需独立核对。
- 跨背景按分布平均返回未接通；平均分布未决定或固定背景未决定继续补问。
- 处理后筛选、背景总体不明确、仅有无条件 A4 或未确认条件随机化，不能批准新的背景审核。程序不靠关键词猜测它们有效。
- 不改变无条件旧请求；不把明确背景自动接入其他尚未支持该交接的读取家族。
- 仍保留原两政策入口的 `SYNTHETIC_TEST` 研究限制，不获得生产准入或估计交接许可。

## 验收与复现

`tests_gateway/test_contrast_conditioning.py` 覆盖 R1b/R2 POINT、有界和均值顺序 PARTIAL、缺项与拒绝、背景/方向/名单变更、假设放宽、重读与保存恢复，以及修改背景后的证书拒绝。新增检查登记在 chain/full，quick 不扩张。它们是手写候选与合成审核，不能报告为 LLM 准确率。

原被挡住的八小时营业参考题，原文与 A0 语义未变，现在进入 `READY_TO_READ → REVIEW_REQUIRED`。新增科学审核故意保留待定，后端不调用；没有事后补条件把它计为成功。记录在工作区 本地实验记录（不分发）。本轮不调用 API。

本轮分批验收通过：31 项新增检查、253 项既有兼容检查、12 项验收登记检查，共 296 个不同检查；不是全量框架或真实模型准确率验收。原始运行及最终节点汇总保存在同一工作区目录。六个合成案例另保存完整材料、候选、审核计划和执行结果。
