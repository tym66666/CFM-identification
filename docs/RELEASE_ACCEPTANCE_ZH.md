## 本轮改变什么

- 对齐观察性设计与未知分配律的 Schema，未知保留为未知，不编造分配概率。
- 后台先复核并定位实际字段问题，再进行有界重读；新回答仍需完整变化与来源审核，真实额外条件不自动删除。
- 均值顺序的结果定义一致性要求贯穿请求、解析和诊断。Skill 对齐已有关系字段的职责，区分明确拟采用、不采用和未决定；科学批准仍独立。
- 当前能力、读取配置、开发落点和限制说明统一到 8 类事实家族、18 个方法。数学 Core 未修改。

团队网页保留同门的主估计先完成、baseline 按需运行及 Policy 接口；额外修复 Windows 下中文 JSON 的 UTF-8 读写。个人网页仅接 Identification，不引入估计／策略依赖。

## 真实模型与网页检查

本轮使用无头 Chrome，从原示例和原附件开始，通过真实页面提交并调用 LongCat-2.5。没有注入参考 JSON、修改模型答案或给正例补条件。以下为已知材料的开发复测，不是独立盲评准确率。

| 网页运行 | 读取与复查 | 实际结果 |
|---|---|---|
| 校园反冲突邀请、同伴效应 | 目标复核有一次聚焦检查；事实无需重读 | POINT；公式与独立证书重放通过 |
| 四店推广、均值顺序差值 | 事实有一次格式复查及聚焦审核 | sharp PARTIAL `[1/5,1]`；独立重放通过 |
| 顺序是否采用尚未决定 | 原文在调用前已固定；后台聚焦复核后仍保留未知 | NEEDS_INPUT；未调用求解器，无证书 |
| 原前门题，第一次 | A0 goal 未按对象格式输出，格式复查仍未改正 | 停止于读取格式，未生成数学结论 |
| 原前门题，再次从头运行 | 将“没有网络干扰”写入对象关系网络，复核未纠正 | 研究结构歧义，未生成数学结论 |

两份成功结果的公式由实际证书渲染，条件来自实际审核记录。页面无 JavaScript 异常，技术审核默认折叠；PARTIAL 在手机宽度无横向溢出。正例仅由审核者对预先声明的合成条件作一次科学确认，负例不确认未知条件。读取复查与科学批准不是同一动作。

此前 GPT 接口修复后的前门 POINT、均值顺序 PARTIAL 和未决定负例已取得对应结果；原九例模型比较仍保留其原始成绩，不能用开发复测改成 9/9。本轮 LongCat 前门失败表明，合同对齐没有消除模型的格式和字段归属错误。

## 当前结论与限制

可发布的保证是：已有接口、审核边界、结果显示和安装路径可复现。不能保证任意自由文本首答成功，也不能保证后台模型复核总能发现误读。DAG 与对象网络混淆是仍需保留的已知模型限制；当前不继续为单题追加 Prompt 规则。完整能力及后续范围见[当前能力](CURRENT_SCOPE_ZH.md)与[已知限制](KNOWN_LIMITATIONS_ZH.md)。
