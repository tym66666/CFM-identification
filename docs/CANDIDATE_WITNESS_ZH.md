# 识别库外候选的两世界附件与反馈修正

## 入口与边界

- 初次候选：`evaluation.business_candidate_schedule.evaluate_with_candidates`。
- 单次、显式反馈修正：`evaluation.business_candidate_feedback.evaluate_with_candidates`，另传 `prior_envelope`。
- 有限附件检查：`evaluation.witness_schedule.inspect_two_worlds`。
- 依据重算结果展示：`evaluation.candidate_schedule_presentation.render_zh`，必须提供由已审核 typed inquiry 生成的数学输入。

原 v0.35.3 仍负责真实 Core、业务和科学审核、目标绑定及候选许可检查。本版本没有改动数学 Core、Estimation 或 Policy。没有为真实业务自动生成科学批准。

候选外层是 `candidate-envelope-v0.37`，包含原 CandidateProposalV011 和可选 `two_world_schedule`。这是新增的明确协议，不是删除模型多余字段以修复旧输出。原始完整模型输出保存不动；额外字段、错误绑定和未批准假设仍被拒绝。

## 附件含义

每个世界包含一个默认结果向量，以及有限个完整分配的覆盖项。它们共同定义所有二元分配下的确定性潜在结果表。节点顺序和目标权重沿用已审核输入。数值是严格有理数字符串，禁止代码求值。

当前检查器范围很窄：合成停机小时、固定政策均值、最多10个独立伯努利随机化簇、NODE_FULL_LAW/FULL_JOINT_LAW 的符号观测算子，以及五项明确许可：分配律已知、完整分配随机化、一致性、网络预处理固定、有限条件一阶矩。更强的无干扰、均值暴露充分性等不在本检查器支持范围。

当前附件数值限制在 [0,1]，这是检查器选用的一个足够小的构造类，**不是业务停机小时范围假设**。超出此范围意味着附件未被这个检查器处理，不应直接判数学错误。例如本轮第一次的10/20附件虽然超出范围，但另有正概率分配下结果不同这一明确数学错误。

检查器用 Fraction 精确枚举所有正概率分配，检验观测结果逐节点相等，并计算原目标在两世界中的值。它不能验证任意自由形式证明，也不能证明某个给定观测边界上总存在非唯一性。

## 三种状态分别报告

1. Core 原状态和证书重放。
2. 原候选格式、目标绑定、A4/A5许可检查。
3. 附件中具体构造的精确核对。

`PASSED_EXACT_CONSTRUCTION` 不会改写 Core 的 UNSUPPORTED，不新增 Core 证书，不批准 Estimation/Policy。模型全文仍是 LLM_UNVERIFIED。展示层重新计算附件事实，不能只信保存的通过标志。

## 显式反馈修正

v0.37.1 每次仍只发一次请求，没有自动循环。它先验证旧输出属于同一目标和科学条件，再从旧表生成至多两个正概率分配上的具体不一致记录。发送旧模型输出与这些错误，不发送正确反例。此前失败保留，修正效果单独统计。

识别结论针对当前固定假设集。未来增加强假设可能使目标可识别，不妨碍在当前假设集下给出有效的非识别反例。

## 2026-10-21 真实开发测试

同一道 G32-08，沿用此前真实业务规范化结果，未修改自然业务文字。

- 无反馈 A：72.343秒，提出 NOT_POINT，但两个世界在可观测分配下分别为10和20，反例错误。
- 无反馈 B：39.359秒，回答 UNDETERMINED，没有反例附件。
- 对 A 的一次反馈修正：101.484秒，附件通过；16种支持分配的观测结果均相同，目标分别为1和0。

修正回答原文仍误称两个 default_outcomes 相同；实际为1与0。它们之所以观测等价，是覆盖项在所有16种支持分配上给出相同结果。因此不能把“附件通过”报告为“整份回答通过”。

无反馈附件通过是0/2；反馈修正通过是1/1，不能合并为独立成功率，也不代表21题Benchmark表现。共3次 LongCat 调用，无 DeepSeek 调用。原输出、冻结请求、错误反馈、重放结果和审查记录均保留于 外部实验档案（不随发布分发）。
