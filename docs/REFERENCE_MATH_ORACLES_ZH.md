# 小网络精确验证：为什么我们不只依赖模型写出的公式

运行 `python -m evaluation.math_oracles`。脚本用 N=4 处理向量枚举和 Python `Fraction` 计算，结果不受浮点误差影响。

1. **固定配额下完整分配零支持**：四人恰好两人 treated 时，`q(1111)=0`，而 `q(1100)=1/6`。前者不能仅用 R1b 完整分配正支持定理处理，后者可以。
2. **R2 通过签名支持处理零支持完整政策**：每个员工指定一位核心合作者。虽然 `q(1111)=0`，但 `P(T_i=1,T_core=1)=1/6`。在额外接受的均值签名充分性假设下，`V(1111)` 可表示为对应签名均值加权和。
3. **加权暴露不需要真实充分性**：构造依赖具体被处理邻居身份的 `Y_0(t)`，在 iid 随机化与正支持下，设计标准化 arm mean 等于对应观察条件均值。这里不能推出任意固定完整政策值。
4. **四臂均值相同但完整政策值不同**：N=4 完全图，两个因果世界只在同一 arm 类别内交换正负潜在结果，所有 node-arm conditional means 一样，却在固定 `z=(1,1,1,0)` 下得到不同收益。故压缩 A4 不足以确定该完整政策目标。
5. **观察性混杂的双世界**：两世界都有 `T=U, Yobs=T`；世界 A 无处理因果效应，世界 B 处理效应为 1。故仅靠观察律和 consistency 不能唯一确定 ATE。
6. **零支持 arm**：某个员工 `p_i=0`，他被处理的 arm 支持为 0；不能把未定义条件均值贴成 PARTIAL。
7. **设计标准化的直接 contrast 不等于固定他人处理的直接效应**：在四人恰好二人处理、核心邻居是节点 1 时，令 `Y_0(t)=10t_2`，则 `mu_0(1,1)-mu_0(0,1)=-5`，但固定其他人的处理后改变 `T_0` 的结果始终为 0。
8. **iid 完整分配虽极其稀有却有正支持**：四人 iid 1/2 下 `q(1111)=1/16`；推广到 300 人则为 `2^-300`，总体 POINT 并不表示有限样本容易估计。

限制：脚本针对明确列出的具体反例和定义进行计算，不能取代一般随机化识别定理的证明，也不构成真实网络业务因果假设的科学核查。
