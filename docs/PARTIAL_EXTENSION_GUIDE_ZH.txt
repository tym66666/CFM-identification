PARTIAL 扩展框架：共用审核链，每条路线独立承担数学责任

目的与范围

当前工作的目标是把一个可靠的参考路线、明确的接入边界和可复用的验收方式搭好，
使后续贡献者能沿同一结构扩展问题族。不需要项目作者亲自实现每一种 PARTIAL。
框架可扩展，不等于所有部分识别问题已解决，也不等于新增模块自动获得认证。
这份指南没有新增定理、通用求解器、运行时自动注册或科学审批机制。

一、先区分三类扩展

1. 同一数学合同下的新业务参数。
   改对象名字、网络边、名额、完整政策、评价名单或合规总体均值，继续用现有
   参数化入口。不要按“物流题”“维修题”或某个案例名称另写识别分支。
   examples/bounded_policy_intake_fixture.py 与
   evaluation/bounded_policy_generalization.py 已示范这种参数化结构测试。

2. 仍是网络政策均值，但新增 D/E、额外假设或不同信息结构。
   先明确新数学模型及证明，再实现独立合同、求解、证书与验证。若只是另一种
   已知随机化设计，也必须重新核实支持计算与可达性；不能只改一个枚举标签。
   单调性、平滑性、聚合等式、多来源或完整联合分布可能产生耦合，不能直接
   沿用“各未知单元分别取下界/上界”的构造。

3. DAG、IV、观测性调整等不同问题族。
   可复用业务材料、目标审核、来源绑定与结果展示原则；需要自己的科学合同、
   适用条件、证明和验证适配。不要塞进 D2/E1 的声明字段或冒用 R2 审核路线。

二、哪些共用，哪些由路线自己实现

共用的职责应保持稳定：
  cfm_id/business_entry.py：构造业务读取请求。
  cfm_id/question_bound_assignment.py：当前问题绑定、政策/评价对象和原分配事实。
  cfm_id/assignment_review.py：分配事实与来源的独立审核。
  cfm_id/intent_submission.py：既有材料、业务目标、A4/A5、路线与 Core 审核链。
  cfm_id_bridge/scientific_binding.py：现有规范化哈希工具。

有限 D2/E1 是参考实现，不是所有 PARTIAL 的父类：
  bounded_policy_intake.py：prepare 只生成未审批表；compile_reviewed 只编译输入；
    submit 把实际读取生成的合同与原独立 context 比对，再走既有审核链。
  bounded_policy_contract.py：路线特有的类型、适用域、完整信息范围与相容性。
  bounded_policy_solver.py：界限公式、证明项、上下端点见证。
  bounded_policy_verify.py：自行枚举、重算支持、检查全部 A4 与端点可达性。
  bounded_policy.py：显式审核后的接入与结果发布；重放失败不发布区间。
  以上路径均位于 cfm_id/。

新路线应保留这五种职责的分离，但不必照搬每个类或 R2 专用字段。
先有第二条真实路线，再依据实际重复抽取共用代码；当前不改造数学 Core。
路线清单或接口符合性只能说明“有这个模块”，不能批准假设、替换审核或发布结论。

现有有界入口仅接收已经审核的 R2 POINT，或 R2 实际确认的
ZERO_POLICY_SIGNATURE_SUPPORT。其他 UNSUPPORTED 原因不会自动转成 PARTIAL。
新路线必须写清自己的入口条件，不能继承一个“失败后就求界”的通用回退。

三、每条路线先写清的数学合同

合同至少包括：目标与坐标；对象/网络/干预空间；原分配律；完整 A4 信息；每项 A5
及其作用域；结果取值与边界；额外约束；软件资源上限；明确排除的情况。
要说明研究的是给定 W=w 的目标，还是另行定义的总体平均，不能静默混用。

区分两种数学问题：
  全局识别问同一模型类中，任意可行观测信息是否唯一决定目标。
  给定实际精确总体信息 b 的识别集合，是 {theta(M): M 满足完整条件且 O(M)=b}。
某个内部 b 的两世界反例不意味着任意边界 b 都非唯一；边界 b 可以使区间退化。
当前 bounded_policy 计算给定所列精确均值及科学边界下的集合。

必须分开报告：
  POINT：集合是单点，仍需有效证明。
  PARTIAL + sharp：给出的集合恰好等于识别集合。
  有效外界：所有可行目标都落在界内，但没有证明每个界内值可达。
  informative=False：相对声明的逻辑范围没有收窄；这仍可能是 sharp 的集合。
  INCOMPATIBLE：所给信息和假设不可同时满足，不是一个普通识别区间。
  NEEDS_INPUT：事实/数值缺失；REVIEW_REQUIRED：条件尚未审核。
  CHECK_BLOCKED：格式、绑定、审核或证明校验失败。
  UNSUPPORTED：该软件入口未覆盖；不代表数学非识别或不存在其他定理。
外界是后续路线可能承担的结论类型，当前参考路线只发布已重放的 sharp 集合。
LLM_UNVERIFIED 候选仍属于未认证研究建议，不可计入上述认证成功率。

sharp 需要两个方向：所有可行模型都满足界；界内值确实来自合法模型。
有限参考模型给出两个完整端点世界，并用凸性证明中间值可达。别只提供优化器
数值或可行端点：端点可行不证明没有更极端值，单有有效界也不证明 sharp。
若未来模型不闭、非凸或识别集合不连通，应使用对应的极限序列、集合证书等；
不能把“下确界与上确界”自动写成可达闭区间。

边界必须声明是潜在结果几乎处处有界，还是条件均值有界。二元均值 1/2
不是一个合法的确定二元结果，需提供相容的随机结果实现。
E1 暴露定义不蕴含全安排均值充分性；有限样本均值也不是精确 A4 总体等式。
完整联合分布、非目标节点限制及零权重节点的 A4 均不能为了得到简便界而丢弃。

四、一个可完整说明的已有参考

见 examples/partial_extension_reference.py 的 partial_missing_signature：
四个小组甲—乙—丙—丁，原试点四选二且名单等概率。问四组全使用、四组等权的
按时完成率。另行审核全安排均值充分性、随机化等条件；结果为二元；给定完整
声明清单中的精确总体均值。这些数值来自独立合成协议，不是 LLM 估计。

全员政策下，甲、丁的目标签名有支持，乙、丙的目标签名零支持。
V = (h_甲 + h_乙 + h_丙 + h_丁)/4，h_甲=5/6，h_丁=1/2，0<=h_乙,h_丙<=1。
因此 sharp 集合是 [1/3,5/6]。上下端点世界还必须保留所有其余已给 A4 单元。
缺少“只评价谁”时应先补问；缺少科学边界时不能自行默认 [0,1]，除非明确的
二元结果定义及其作用域已纳入审核合同。未审核均值充分性时不能发布上述界。

这是单个政策均值的非负归一化加权问题。两个政策各有 sharp 区间，并不保证
相减得到差值的 sharp 区间；差值必须在同一个完整可行模型上处理共享未知量。

当前实现限制：D2、E1、处理前固定简单无向网络、n<=12、一个精确均值来源、
无额外耦合限制、单个固定政策均值。业务入口接明确评价名单的等权均值；数值
后端另有非负归一化权重验收。仅合成科学审核，production_admission=False，
不进入 Estimation/Policy。节点上限是穷举验证预算，不是数学定理的节点上限。

参考适配器还包含：point_observed_policy 为 POINT 3/4；
sharp_but_uninformative 为 sharp [0,1]；point_from_declared_bounds 为 POINT 0。
最后一例的逻辑范围本来就是 [0,0]，因此 informative=False 不与 POINT 矛盾。
这四例改变了政策、图或科学边界，是不同验收情境，不是同一问题逐步放宽假设
的演示。该适配器总计 4 个正例、9 个早期阻断负例，正例各检查 3 类重算哈希的
证书篡改。其作用是示范扩展接入和验收，不能替代新路线更全面的专门测试。

五、可执行的扩展验收骨架

evaluation/partial_extension_acceptance.py 是离线 Protocol 骨架；
examples/partial_extension_reference.py 提供现有 D2/E1 路线的显式参考适配。
调用方提供 route_id，以及 cases、prepare、run、certificate、replay、tamper
六个方法。骨架检查未审批准备、预期结果状态与区间、证书重放、重算哈希后的
篡改拒绝，以及早期负例阻断。参考适配器的 run 使用原完整审核链；其他适配器
是否保留科学审核与验证独立性，仍需审查实现，不能靠方法名证明。
全过程不调用真实 API。
这些钩子用于开发验收，不构成生产插件注册，也不授予任何审核许可。

预期值应来自预先写明的手算、独立枚举或其他已核实参考，不能把待测 solver
的输出再当作 gold。replay 应采用独立计算路径；只重算哈希不是数学验证。
共享输入校验必须披露。当前验证不是 Lean/Coq 形式证明，也不认证审核人身份。
一个伪造证书被拒绝并不涵盖全部攻击，骨架通过也不能自动证明一个新定理。

在源码目录运行（输出文件必须尚不存在）：
  python -B -m evaluation.partial_extension_acceptance --output partial_reference_acceptance.json
  python -B -m unittest tests_gateway.test_partial_extension_acceptance -v
其余原路线数学与完整链回归见 tests_gateway/test_bounded_policy.py 和
tests_gateway/test_bounded_policy_intake.py；结构生成验收见
evaluation/bounded_policy_generalization.py。离线命令不能替代真实模型测试。

新增路线交付前至少逐项补齐：
  1. 文献、确切命题、A4/A5、完整模型与 sharp/外界证明；标明不是文献原有结论的推导。
  2. 参数化声明与实际业务目标的无损编译；任何缺项均不从参考答案填补。
  3. 显式适用域和失败状态；未审核、已否定或过期来源均不能求解或发布区间。
  4. 精确证书与独立重放；全部 A4、全部模型限制、上下界有效性和所声称可达性。
  5. 单点退化、真正区间、无信息收窄、不相容、缺项、越界和篡改负例。
  6. 参数变化与不变性：节点改名/重排，目标不变下收紧可行约束不得扩大识别集合。
     比较必须保持同一目标、同一观测信息和相容的嵌套模型，不靠切换问题制造“梯度”。
  7. 新旧审核链兼容回归；证明失败不发布区间；旧 POINT 结果与新证书分别保存。
  8. 冻结的新业务文本与独立标签后做真实 LLM 验收，分别报告格式、目标语义、
     条件阻断和认证识别率；结构 Mock 的通过数不能充当 LLM 准确率。

上述材料齐备后才讨论显式接入。框架成熟的标志是新增路线能说明自己在哪些
条件下正确、在哪些条件下必须停下，而不是每一个输入都得到一个数值区间。
