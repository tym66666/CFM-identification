# 网络事实的来源审核

## 2026-11-01：错误类型与识别影响分别报告

严格来源审核新增 `source_review_diagnostics`：把 `MEANING_OR_FIELD_ROLE`（含义、状态或字段归属被拒绝）与 `CITATION_COVERAGE_ONLY`（仅引用覆盖被拒绝）分开。它是诊断，不改变审核结论、请求绑定、科学许可或数学调用；原始回答不修补。

“仅引用失败”不自动等于“无关说明”。当前 `/study` 同时包含节点、变量与研究背景，`study.context` 会进入数学目标及绑定。记录级审核只拒绝 `/study` 时，程序不能断言错误在无关文字，也不能断言数学值一定错；诊断明确标为 `MIXED_STUDY_RECORD_CONTEXT_ENTERS_TARGET`。对单个解释性短语的影响判断应另列人工核查依据，不能凭字段名放行整个记录。

均值顺序候选读取配置将 context 限定为研究时期及真正限定目标的背景，避免要求模型把业务故事再次写进数学字段。已有的 `unresolved` 备注仍按独立备注审核处理；目标、科学条件、信息范围和有限模型完整性不能变成备注豁免。维护模块为 `cfm_id/source_review_diagnostics.py`；不在评测代码中另造批准规则。

## 2026-10-31：材料交接与两种结果

显式启用 `material_handoff="information-inventory-1"` 后，固定政策均值、两政策差值读取会接收 A0 已审核的 `sample_data_description`、`available_information` 原文位置清单。清单不复制 A0 的解释作为事实，不自动补回答、引用或科学许可；A0 的信息分类仍须对照原文复核。其他读取族尚未接此选项，显式使用会停止，不静默忽略。

`fact_source_review.prepare(entry, candidate)` 和现有 `source-review-plan` CLI 按会话选择工作表。新会话必须完成 `fact-source-impact-review-1`；漏传审核或传旧审核不会进入数学方法。旧会话继续使用原有严格审核，旧失败记录不改写成成功。

| 问题 | 报告与处理 |
|---|---|
| 目标、比较方向、评价对象、设计、总体信息、科学条件错误，或关键引用不足 | 识别相关或影响尚不明确；继续阻断、定位复查 |
| 已填写的样本覆盖名单没有原文依据 | 继续阻断，不能按“只是样本信息”豁免错误字段 |
| 纯估计记录说明整项遗漏，且经下述独立审核与依赖检查 | 材料不完整；可继续原有 POINT 条件审核，不能记为完整读取通过 |
| 原文科学条件未定或明确拒绝，模型正确保留 | 读取可以通过；数学流程仍按缺项或拒绝停止 |

第三行仅限：完整原始文档由审核者确认**只有记录说明，不包含数值、变量定义或科学条件**；该文档不被其他 A0 字段或事实字段使用；另有独立来源的符号总体联合分布／逐对象总体分布；当前不存在有限模型输入。程序检查引用依赖，内容分类仍是独立审核判断，并非程序证明自然语言语义。不会自动删除限制、挪动记录或补总体信息。它只适用于现有固定政策 POINT 路径，不能用于 PARTIAL 模型完整性或 sharp 界限。

新结果分开保存：

- `reading_assessment`：格式、字段归属、值与状态、引用审核、材料完整性及逐项问题。
- `identification_assessment`：实际执行状态、是否调用数学后端、是否通过独立重放。审核通过本身不等于识别成功。

`COMPLETE + NEEDS_INPUT` 表示读对了缺条件材料；`INCOMPLETE + POINT` 只在上述窄范围成立，必须保留遗漏告警。任何关键字段拒绝都不能得到已认证结果。新请求、原答或审核内容变化后，原审核仍作废；显式重读继续要求完整变化审核。

维护位置：`reading_material_handoff.py` 管原文清单、当前来源映射和交接；`reading_impact_review.py` 管材料逐项审核、窄范围非依赖检查及双结果报告；`fact_source_review.py` 管共享字段审核与合同选择；分派器只接线。运行代码不导入参考答案，数学 Core 不变。详细本地验收见 [材料交接验收](READING_MATERIAL_HANDOFF_ACCEPTANCE_ZH.md)。

## 解决什么

读取稿中的“额外限制”未必真是数学限制。例如，模型可能把“只收集有限回访记录”或“总体均值以符号给定”错放进去。直接把这类答案送到方法检查，容易将读取错误报告为数学覆盖缺口。

新增 `fact_source_review` 在方法检查前，分别审核每条记录的 **字段归属、值与状态、实际引用覆盖**，另检查整份回答是否遗漏原文。审核者需要看原材料；程序不按关键词判定语义，不自动删除、移位或补充模型答案。

| 来源审核结果 | 后续行为 |
|---|---|
| 任一维度拒绝 | `READING_RECHECK_REQUIRED`；保留原答，定位字段后显式重读 |
| 尚有待审，且没有拒绝 | `REVIEW_REQUIRED`；不检查数学方法 |
| 来源审核全部接受 | 进入原有目标、A4、A5、支持条件检查及证书流程 |
| 全部接受，但确有当前方法不支持的额外限制 | 保留限制，由原有适配器报告覆盖缺口 |
| 全部接受，但原文确实没有总体信息或科学条件未决定 | 原有缺项与追问流程继续阻断 |

来源审核不是科学批准，更不证明点识别。错误的人工批准仍可能导致错误的业务解释；哈希只保证审核对象未变，不证明审核人的身份或判断正确。

## 调用与兼容

本层是**显式选择的新输入**，不是所有旧调用的强制前置条件。未传 `source_review` 的旧接口保留原有行为与原生审核。新应用可按以下顺序接入；用户不需要选择 R1a、R2 或 R3。

1. 用当前 reader plan 和模型原答生成工作表：`cfm_id.fact_source_review.prepare(entry, candidate)`。
2. 独立审核所有字段的三个维度，以及空路径 `""` 表示的整份读取完整性。审核记录含当前绑定、权限类别、审核人、理由和当前原文来源。
3. 将审核记录作为 `source_review` 同时传给 `business_dispatch.inspect_methods`、`execute`，或整题 `business_case` 对应子问题。
4. 继续完成原有计划审核、事实审核、科学审核、研究协议选择及独立证书重放。任何一种审核不能替代另一种。

CLI 工作表入口（单行运行）：

```text
cfm-id-dispatch source-review-plan --intake intake.json --query q1 --query-review query_review.json --reader-plan reader.json --candidate facts.json --output source_worksheet.json
```

此命令只生成待审工作表，不能把工作表直接当作已批准记录。完成独立审核后，在现有 `method-plan` / `execute` 命令中增加 `--source-review source_review.json`；其余必需参数保持不变。CLI 拒绝覆盖既有输出。

下游计划绑定来源审核记录。已经据此签发的计划及原生审核，不能在执行时通过删除、替换来源记录来复用。重读后须生成对应新请求、新原答的来源审核，并完成所有实质变化审核；二者分别绑定，之后共同进入下游计划。新增材料也必须重新审核。

当前覆盖四个网络事实读取族：固定政策均值、两政策差值、随机化局部效应和观察性完整政策均值。暂未为 DAG 接入该新工作表；显式传入时拒绝，不会静默忽略。原有 DAG 审核不变。

## 引用与字段职责

工作表显示原字段的直接引用，以及读取协议已经明确提供的 `definition_refs`，两者分开展示。父字段、其他字段或审核人临时补列的来源，不能修复候选字段的漏引。R3 当前没有显式定义依赖字段，因此向量概率行仍需自己的引用覆盖行值、对象顺序及编码；程序不自动借用表头。

`additional_restrictions` 仅容纳尚未由专门字段完整表达的真实限制、额外总体信息或指定方法；有限记录和符号表达等资料说明应在相应信息字段保留。真实未定条件仍应保留未知，不得从“未定”改成“拒绝”，或从资料说明推导科学许可。

| 模块 | 唯一职责 |
|---|---|
| `cfm_id_llm.fact_source_contract` | 三个审核维度、公开字段职责、引用原则；不生成 Prompt 或分类原文 |
| `cfm_id_llm.fact_wire_models` | 从已登记 reader/profile 选择格式模型，供来源审核与类型诊断共用；不选择数学路线 |
| `cfm_id.fact_source_review` | 生成工作表、验证来源审核、绑定原答；不补写字段、不判定定理 |
| `business_dispatch`、`business_case`、CLI | 将显式审核传至原有适配器，并保留回执与旧接口 |
| `evaluation`、`examples`、`tests_gateway` | 实验、合成审核夹具和正负例；运行模块不导入这些参考答案 |
