## 实际验收结论

同一组 32 份合成材料（30 份网络相关、2 份 DAG），DeepSeek 与 LongCat 分别运行旧配置、
首版通用候选、两端顺序修正版，共 192 次 A0 首答。另有 13 次明确 A0 复查与 11 次事实读取。
前置调试 21 次另计。本地未发送 HTTP 的预检失败不计 API 调用。

修正版没有显示整体优势，不启用为默认。它在 LongCat 上频繁出现枚举对象化；两模型仍有
背景、目标同伴状态和标准化规则的字段混淆。修正两端接口减少了一部分方向错误，但没有
解决整体负担。该结果属于这次**通用化实现**，不能回填为此前窄范围薄 A0 的结果。

最终定向离线检查：251 passed，含旧协议、审核、重读、政策 POINT/PARTIAL 与证书兼容检查。
离线测试不等于 LLM 准确率。真实首答链路中一份旧方法 DeepSeek 回答取得 POINT 并独立重放。

## 解释结果时必须保留的限制

1. 完整字段、引用与审核通过，和模型抓住主要目标是不同指标；报告分别保留。
2. 部分测试材料重复使用“同一经营背景”等模糊说明；其被填成固定条件既反映接口负担，
   也反映材料歧义，不可全部归因为模型能力。
3. 前 18 份材料使用同一六店结构的设计/暴露/目标变体，不是 18 个独立场景。
   本轮是开发验收，不是独立盲评，也不是完整 NBIB 准确率。
4. 16 份实际调用 document_intake 读取本地 MD，其中两份附 CSV；CSV 使用 schema-only 模式。
   没有验证浏览器上传界面、扫描 PDF OCR 或所有附件格式。
5. 仍存在 Schema 可表达而本地解析拒绝的状态组合，以及可省略字段给模型造成的填写负担。
   在实验协议冻结期间没有静默修改 Schema 或修补回复。

后续应先把通用接入重新对齐薄 A0 的字段所有权：整政策题不要再承担局部同伴状态，
普通期间/场景不要重复变成条件层，分类与条件表达不要互相推导。不要继续用追加长 Prompt
或修改业务原文填补这次接入的缺口。完整旧链路与候选原答均保留，直到替代方案有新的证据。
