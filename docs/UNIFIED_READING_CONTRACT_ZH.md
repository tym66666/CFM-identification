完整实验组合可通过 [研究配置文件](../examples/legacy/configs/previous_research.json) 复现。冻结后的新材料组织及重复验收见 提交检查（历史实验记录不随发布分发）：事实首读 4/4，但重复读取 1/2，仍观察到结果定义附入处理编码。此处记录实验设置，不承诺首答稳定，不默认升级配置。

`inline-unified-contract-3` 进一步分开研究对象与该对象的结果事件、有限样本与可观察总体信息、已有信息与潜在结果科学限制。原文以任务或订单本身为研究单位时仍保留该单位；真实可观察总体区间仍是信息，不能一律归入科学界限。A0、显式重读和逐字段审核使用同一份当前字段定义，复查只发送源码中的职责说明及原文定位，不发送审核者的替换值、私有理由或预期结论。旧协议的定义与绑定保持不变。

本项针对读取说明的不一致，不增加识别方法，不修改数学Core。保留`inline-evidence-1`的完整JSON类型、来源检查、MISSING投影、comparison_order、逐字段独立审核及既有原生重放。只替换模型可见说明；没有在程序里用“本人”“同伴”“政策”等词自动改字段。

## 先前修正：类型、字段状态与引用覆盖

`inline-unified-contract-4` 把枚举的原样字符串、合法选项、值类型和对应引用字段放在一起，避免将枚举误写成 claim 对象。引用规则改为“本字段自己的全部引用共同支持该字段”，不要求每一条引文单独支持整个值，也不允许借用其他字段的引用补证据。

`inline-unified-contract-5` 在此基础上，从既有字段规则生成每个 claim 允许的状态：不适用只在本来允许的字段使用，不放宽 Schema。评价对象须同时有问题指定的评价范围及写出的名称依据；跨对象等权平均放在 aggregation，不能重复当作针对协变量、暴露或分配状态的标准化分布。显式复查只发送原文位置和这份公开字段合同，并要求保留其他正确字段及其引用，不发送预期识别答案。

对应网络事实说明可选 `network-source-selections-information-3`，仍使用同一个事实 Schema 和解析器；强调长枚举的精确写法及各字段自己的名单、编码、时期依据。信息表的辅助定义引用应保留，不得为适配接口而删掉有效引用。相关独立来源审核见 [网络共同入口](NETWORK_POLICY_DISPATCH_ZH.md#一份信息表及其辅助说明)。这些选项用于冻结实验和旧请求兼容，不代表新增识别路线或用户入口。

## 统一的字段分工

| 问题 | 应保留什么 | 不应混入什么 |
|---|---|---|
| 逐个对象比较本人的两种行动 | 本人两端、固定或平均的同伴条件、最终对象范围与汇总 | 逐对象比较并不自动构成全体同时实施的共同政策 |
| 本人不变，比较同伴状态 | 本人固定状态、同伴两端、评价对象与汇总 | 不改为本人处理效应，也不补全体名单 |
| 评价或比较完整政策 | 主政策完整安排，比较时基准另存；评价子集与完整处理名单分开 | 不因只评价一个对象而删掉其他对象的处理安排 |
| 定义同伴暴露 | 计数、比例、阈值等原文定义及孤立点约定 | 定义不等于本题指定的状态，不自动声明均值充分性 |
| 目标条件与方向 | 基准内容、增加/减少方向独立读取 | 基准未定不把已知减少方向变为未知 |
| 可用信息与样本 | 原文声称的总体信息、有限样本分别记录 | 不把“未给总体均值”当成已知总体值 |

局部条件下的单状态均值、随机政策价值、政策选择、一般ATE/CATE和变量干预分布仍保留各自候选类别，不为适配现有业务桥而改类。字段全部有严格类型；声明不适用、未提及、明确缺失三者保持区别。一般清晰负句不等于缺失；未给值也不能写null。

## 请求与兼容性

`compact_formulator.make_compact_request`只在显式选用本项时替换System Prompt。字段说明在相同Schema上替换，不把新说明继续追加到旧说明后面。可继续使用`joint-assignment-law-1`的共同分配词典；`target_summary_contract`只能为默认空或`target-summary-3`，显式较早目标合同不会被静默覆盖。

旧协议的实际请求与保存文件保持不变。不同Prompt生成不同请求绑定；旧候选、旧审核不能直接复用。新回答仍可进入有来源定位的显式重读，保留原回答与变动审核。程序不修补来源、null、状态或目标。
