## 改了什么，仍由谁判断

新增 `cfm_id_llm/source_coverage_contract.py`，根据公开 Schema 声明每组引用负责哪些字段。局部效应读取器已接入，例如：

| 引用位置 | 负责内容 |
|---|---|
| `study.source_ids` | 对象、网络、处理、结果及实际写出的背景描述 |
| `target.source_ids` | 目标种类、比较方向、评价对象及汇总方式 |
| `target.first/second.source_ids` | 各端自己的处理状态与同伴状态 |
| `target.remaining_source_ids` | 其余完整安排如何平均 |
| 独立科学条件、总体信息或附加限制的引用 | 各记录自身的声明 |

子记录的引用不能代替父记录，反之亦然。材料跨文档时可以列多个相关来源，也允许在不同记录中引用同一来源；禁止粘贴整个目录、补造缺失事实或将 `NOT_STATED` 改成已声明。说明没有题号、业务名称、标准答案或识别结论。

生成请求时检查公开 Schema 与责任表严格对应。新增字段或引用字段后，如果没有同步明确责任，立即报错；不能静默发出过期说明。它只增加 Schema 描述和请求元数据，不改变回答字段、解析规则，也不自动补引用。请求摘要改变后，旧请求及旧审核不能继续授权执行。

**引用编号有效不等于原文支持该主张。** 自然语言来源审核仍由独立审核步骤完成；程序不会凭“模型引用了一个存在的编号”自动批准。本文中的审核人为开发助手，使用 `SYNTHETIC_TEST` 权限，不能代表真实业务负责人批准，也不是独立盲评。

## 冻结在线测试：保留不完整的首答

模型为 LongCat-2.5-Preview，JSON 模式、关闭思考模式、单请求上限 300 秒。先冻结材料、请求、源码摘要和评分口径，再运行 **16 次**请求，全部返回 JSON；无自动重试、显式重读或模型回答手工修改。没有调用 DeepSeek。

其中 4 次为既有门店两问的新旧说明对照，另 12 次是 6 份新材料各重复两次。新材料来自**两个独立业务情境**：零售门店补货、配送站揽件；同情境改写、重排和重复不能当作独立业务样本。目标覆盖全体、固定子集、单对象，以及反方向的同伴差值。新材料使用明确披露的人工参考 A0，参考答案从未发送给模型，所以本轮衡量事实读取，不衡量新业务的完整 LLM 端到端准确率。

| 新材料 | 两次语义坐标正确 | 两次完整引用通过 | 实际处理结果 |
|---|---:|---:|---|
| 零售，全体对象，材料分文件 | 2/2 | 1/2 | 一次 POINT 和独立重放；一次引用审核拒绝后 CHECK_BLOCKED |
| 同一零售业务，合并材料并重排段落 | 2/2 | 2/2 | 两次 POINT 和独立重放 |
| 零售，明确只评价一个门店，改写比较问题 | 2/2 | 2/2 | 两次 POINT 和独立重放 |
| 配送，固定两站等权平均，同伴低状态减高状态 | 2/2 | 1/2 | 一次 POINT 和独立重放；一次引用审核拒绝后 CHECK_BLOCKED |
| 配送，缺少一致性声明 | 2/2 | 2/2 | 两次均保留 NOT_STATED、空引用，返回 NEEDS_INPUT |
| 零售，另加逐对象逐完整安排的均值下界 | 2/2 | 1/2 | 两次均保留额外条件，返回 ADAPTER_NOT_CONNECTED；一次还有背景引用缺陷 |
| 合计 | **12/12** | **9/12** | 正例 6/8 进入 POINT 并重放；4/4 负例安全阻断 |

“语义坐标正确”检查实际对象、边、分配概率、目标两端、名单、汇总、平均规则、科学条件状态和真实 A4 范围，另人工核对处理／结果文本。它不能代替完整引用通过。负例被挡住也不能抹掉其引用错误。

三份未严格通过的首答分别为：

1. `retail_split_2`：目标两端仅引用介绍业务和处理编码的段落，没有引用真正提出比较的问题；目标父记录也漏引比较方向。
2. `logistics_subset_2`：目标父记录仅引用两端比较的问题，没有引用指定哪两个站、如何等权平均。子记录中出现相关引用不能替代父记录。
3. `extra_bound_1`：背景实际写入了两端共同研究背景与结果定义，但本记录只引用业务介绍和网络。

审核按**实际写出的主张**判定，而不是机械要求固定来源编号。例如只复述简介、评价周及分钟单位的背景，可由简介和带单位的结果定义支持；若写入两端共享背景的额外声明，则须相应原文支持。单对象问题本身点名门店时，其来源可以直接支持名单。未强制复制参考答案的引用列表。

既有门店两问对照中，共同的 `study` 来源覆盖指标为旧说明 **1/2**、新说明 **2/2**；新说明两问均通过完整来源审核，获得 POINT 和独立重放，整题为 `ALL_QUERIES_IDENTIFIED`。旧说明对目标父记录的引用责任较窄，不能把新增责任下的新旧整份成绩当成同口径因果效果。这个小型开发对照不证明普遍准确率提升。

8 个实际获 POINT 的回答（新材料 6 个、已知对照 2 个）另外用 16 或 32 个完整安排的独立枚举，核对原生证书的正支持概率、带符号系数和目标值。枚举允许相同暴露组内的潜在结果不同，不增添暴露充分性。它是有限算例一致性核查，不是业务效果估计或替代证明。

## 离线证据与限制

新增 14 项测试，覆盖 Schema 漂移报错、解析规则不变、旧请求与审核失效、拒绝引用后不调用数学，以及六份参考材料的正负分支。与已有局部效应和登记测试一起，定向回归实际 **98 passed**；不把重叠测试累计。

完整固定框架实际 **1394 passed、133 个 subtests passed**，耗时 944.46 秒，无缺失必需节点，运行期间源码不变。14 个历史案例的请求、方法计划、审核和结果一致；历史研究目录与会话列表一致。离线构建并安装 wheel 后，源码外的 7 个新旧入口正负例全部符合预期；206 个加载的项目模块均来自安装目录，冻结的运行代码与安装内容摘要一致。详见仓库外 `FINAL_SUMMARY.json` 及[固定框架验收](FRAMEWORK_ACCEPTANCE_ZH.md)。这不是全仓库或远端 CI。

证据目录为 `LOCAL_EVIDENCE_NOT_DISTRIBUTED`：

- `PROTOCOL.json`、`PLAN.json`：调用前冻结口径、材料、源码和请求摘要。
- `live/`：不可改写的模型首答及脱敏调用状态。
- `audits/`：逐份来源判断、显式许可／拒绝、实际结果及独立有限枚举。
- `REVIEW_SUMMARY.json`：按阶段与正负例分别汇总，不合成模型总体准确率。

本轮消耗 LongCat 16 次；结束余额为 **73 次**。密钥仅由认证进程载入，没有输出或记录；原始模型结果留在仓库外。

**本次结论是通用引用责任已明确，审核阻断有效，但重复首答的完整引用仍不稳定。** 暂不扩大数学范围。下一步优先围绕目标各端与评价名单的引用责任，研究能否减少重复填写造成的遗漏；任何结构调整都要保留原文可追溯性、独立来源审核和旧审核失效机制，再用新的冻结完整业务材料检验。不能用自动补引、复查覆盖首答失败或只统计安全阻断来宣称已解决。
