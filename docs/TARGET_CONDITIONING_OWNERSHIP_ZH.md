## 一个目标需要分别表达什么

| 内容 | 含义与维护归属 | 不能代替什么 |
|---|---|---|
| 处理／政策及比较两端 | 要干预谁、取什么值、第一端减第二端；沿用逐问行动与政策字段 | 历史处理分配律、实际采用名单 |
| 评价名单与聚合 | 对谁的结果评价，权重是什么 | 完整网络名单、接受处理的名单、背景层的权重 |
| 固定条件 | 本问明确限定在哪组条件下；逐问`conditioning_context`语义槽 | 协变量清单、可用信息、按分布平均 |
| 标准化分布 | 本问明确要求跨哪些条件层、按什么分布平均；沿用`standardization_distribution` | 历史采用概率、已有联合总体分布 |
| 目标时点与业务背景 | 评价期间与必要的场景说明；沿用`time_horizon`及研究背景 | 条件变量、科学许可或精确总体信息 |
| 协变量清单 | 材料提到哪些变量、何时测量、是否可观测；仍属共享材料层 | 这些变量已被指定为目标条件、合法调整集或充分控制集 |
| A4与A5 | 可用总体算子、适用范围，以及独立接受的科学条件 | 目标定义；有数据或固定背景不产生交换性许可 |

`conditioning_context`仅在显式选择新协议时使用，支持 STATED／INTERPRETED、UNKNOWN 和 MISSING，不默认补值。它参加原有逐字段工作表的职责、状态和来源三维审核，不另建审批系统。旧 canonical 草稿保持兼容投影；新条件完整保存在原始候选及 `wire_gate.query_conditioning`，经审核以 `reviewed_target_context` 交接，不能仅消费旧投影后丢弃扩展。

## 两种数学目标不能混在一个字段

本次R3目标是固定完整政策z、评价名单S、已指定处理前条件W=w：

\[
V(z\mid w)=\sum_{i\in S}\omega_i\,\mathbb E[Y_i(z)\mid W=w],
\qquad \omega_i=1/|S|.
\]

若业务另要求跨背景层按某个明确分布q平均，则有限离散情形的目标会是：

\[
V_q(z)=\sum_w q(w)V(z\mid w).
\]

第二式这里只说明目标差异，不宣称当前R3-Full共同入口已经能求解它，更不保证其逐层支持或交换性成立。q(w)、历史分配概率P(T=z|W=w)、评价对象权重分别属于不同含义。原文没有要求按某分布平均，不能从已有P(T,W)自行生成q。

固定条件也不要求原文必须给出每个变量的数值：已有合同可使用明确指定的符号背景w。但仅提到“记录了车型和预约量”，没有说目标限定在哪种背景，就不能自行认定固定W。处理后条件、跨层混合或不清楚的条件仍保留原意，不能为了进入R3而改成处理前固定背景。

## 两个读取阶段怎样对齐

1. A0保留业务目标及逐问条件的原文意义、确定／未知状态和实际引用，不选择定理或批准科学条件。
2. 业务审核确认这是用户所问目标。固定背景与总体跨层平均分别审核；不同子问可以有不同条件。
3. 事实读取按原文表达条件变量、处理前时点和所指背景，连接已有R3的`conditioning.kind/definition/source_ids`；来源审核独立进行，不能借另一个字段的引用补足。
4. 目标审核绑定经过确认的条件表达、完整政策和评价对象。事实阶段改变条件时进入显式复查或新材料版本，不能默默覆盖A0；自由文本相似度或字符串不等不直接作为数学等价判据。
5. 适配器继续调用原生条件检查和证书重放。已有总体信息是否对应同一W，仍由A4范围审核负责；条件交换性仍由A5审核负责。

不能要求所有目标都填写固定W。无条件目标、DAG干预分布和其他已有网络目标须继续遵守各自合同。没有固定条件字段值既不能推出“无混杂”，也不能自动变成新的R3缺项或否定结论。

## 已接入的生命周期与维护边界

- 以显式新读取协议承载新增字段，不直接向所有历史Schema或规范化输出追加字段，避免改变旧请求字节、检查点和审核摘要。
- 字段说明、首次Schema、解析、逐字段工作表、类型诊断、重读路径及完整变化审核从同一职责定义消费；旧协议不偷偷重解释。
- 对旧协议没有表达的字段，不从业务`goal`、协变量或标准化字段中自动补值。旧流程保持原合同；进入需要新语义的流程时须显式读取和重新审核。
- 新协议与旧请求、保存恢复、CLI、逐问和整题入口分别验证；资料补充、更改目标条件和重读后，旧审核失效。
- 先用冻结原失败做回归，再冻结未参与调试的完整业务做少量真实正负例；分别报告语义、引用与执行。原失败修复不能替代新题成绩。

至少覆盖：明确固定背景、明确跨背景分布平均、仅列协变量、条件尚未决定、处理后条件、两问条件不同、评价子集与条件层不同、表内历史分布不作为目标分布，以及引用缺失／错配。研究者不能在看完模型回答后补假设凑成功。

原生 R3 的条件字段及数学目标未变。新协议遇到条件缺失会停下；跨背景标准化目标或其他读取器尚未连接的明确条件目标报告未接通。条件尚未决定继续追问。已知条件不按字符串相似度与事实阶段自动匹配；`fixed_conditioning_matches_reviewed_query` 必须独立审核，拒绝、缺项、待定或过期审核均不能进入后端。

## 冻结新业务的真实读取

一份此前未参与调试的餐饮配送网络业务，两版本仅改变是否明确拟采用条件交换性。两模型各读取两份 A0；只有严格通过的 LongCat 两份继续事实读取。共6次POST（LongCat 4、DeepSeek v4 Flash 2），全部HTTP 200；无重试、无事后修改题目或候选，也未据此继续调整本轮协议。密钥仅由认证进程载入。

业务主问题：三家餐饮店相互借调配送员，下周让春江店和滨河店用排班助手、文苑店不用；在本周已登记的预订量和既定配送范围下，三家每单平均送达时间等权平均是多少？原材料另给合成总体信息与科学条件声明。正例预期经独立审核后 POINT/replay；负例的条件交换性未定，预期 NEEDS_INPUT，不能调用后端。

四份A0均保留了新条件字段；DeepSeek正例仍把固定背景重复写入标准化分布，负例漏读协变量并漏引处理编码来源。LongCat事实阶段的政策101、全部三家等权、固定条件及交换性true/null正确，但将有限记录说明放入额外限制，逐行使用向量漏引对象顺序表头，背景字段也有引用缺口。因此**完整预期分支通过0/4**，没有真实LLM候选获准进入数学后端。负例因其他误读被挡住，不按“反正没有得到POINT”计成功。

未经来源审核的适配器报告了 ADAPTER_NOT_CONNECTED；本轮开发助手对照原文将其定位为读取错误，**不是数学库的真实覆盖缺口**，不能据此触发库外LLM推理。来源审核、读取失败和覆盖缺口必须继续分开报告。此处是开发助手逐项评审，不是独立盲评或总体准确率，材料只有一个独立业务情境。
