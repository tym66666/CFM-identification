# 给导师的 5 分钟展示流程：输入业务 → 输出 Identification

1. **先展示最简真实数学例子（40 秒）**：Path3，D2 恰好处理 2 人，E1 严格多数，节点 0 的 \\(1,1\\) arm。A4/A5 是明示的合成总体许可，Core 返回 POINT、支持 \\(1/3\\)，replay 成功。
2. **一项一项撤假设（60 秒）**：撤掉总体 Arm 条件均值 -> NEEDS_INPUT；撤掉随机化许可 -> 拒绝；只加一条网络边 -> 目标签名零支持。强调不把支持失败说成不可识别的数学定理。
3. **展示常用业务广度（90 秒）**：D1 账号随机、D2 固定名额、D4 团队随机、D5 多部门配额、D6 两阶段和 R3 观测自选择。正式案例均显示“目标 → A4/A5 → 路线 → 公式/拒绝 → replay”，而非人工填入 POINT。
4. **展示输入业务和材料（40 秒）**：在 HTML 输入自然语言、上传 TXT/JSON 或选择 PDF/DOCX/XLSX。前者可以本地预览，后者只登记文件名；导出 `UNREVIEWED` JSON，说明真正业务解析与审核交给 A0，展示页不伪造当场数学认证。
5. **PARTIAL 作为未来路线（25 秒）**：Star7，固定 3 人，E1，只有中心目标签名零支持；若结果有界并接受均值签名充分性，研究区间宽度为 \\(1/7\\)。明确不是正式 R4。
6. **结语（15 秒）**：Identification 负责数学可识别性及正式证明/拒绝；Estimation 和 Policy 都不在本演示中。最多展示一个未经审核的 LLM 候选建议，绝不能与数学结论共用 badge。

## 导师可能会问

**“上传一个业务文件后，为什么没直接给 POINT？”** 因为文件不是可审核的 A4 总体算子、也不是已经批准的因果假设；当前 HTML 只做离线演示的输入采集。完整工作流需要 A0 候选、业务审核、科学审批、Typed Inquiry 和 Core。

**“UNSUPPORTED 是不是不可识别？”** 不是。它说明当前实现的正式路线不适用或无法认证；数学上的 NON-ID 需要额外的观察等价因果世界等证据。

**“区间是不是已经做完了？”** 只有 Star7 isolated research prototype，具备有界假设和极端世界示范，但没有通用 Sharp Bounds 引擎或正式 R4 证书。
