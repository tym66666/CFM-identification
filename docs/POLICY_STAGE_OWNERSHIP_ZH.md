# 固定政策业务的阶段职责与兼容边界

更新于 2026-11-01。本页覆盖统一入口中的网络固定政策均值、两政策差值，以及 R3 观察性固定政策均值；不新增数学识别机制。

## 同一个问题在各阶段如何保持一致

| 内容 | A0 的职责 | 事实阶段的职责 | 最后由谁确认 |
|---|---|---|---|
| 政策与比较方向 | 保留用户的主安排、对照及减法方向，各一个位置 | 依据原文把已审核意图映射为完整处理向量；不能重新决定比较什么 | 目标与原生计划独立审核 |
| 评价名单和平均方式 | 保留用户评价谁、如何加权 | 核对名单与研究节点，形成数学目标 | 目标审核及原生适用域检查 |
| 时期、固定背景、按分布平均 | 分别保留明确的业务口径，不互相代填 | 从原文核对数学输入所需背景；缺项不猜 | 来源、目标和适用域审核 |
| 记录说明与总体信息 | 定位材料中声称存在／缺少的信息 | 分别读取信息类型、可用性、覆盖名单及各自来源；名册不等于样本覆盖 | 材料逐项核对与 A4 审核 |
| 科学条件 | 保留原材料，不批准假设 | 读出已采用、提议、未定、拒绝等声明 | 研究者独立审核；随机设计或暴露定义不能代替许可 |
| 识别结论 | 不判断 | 不生成认证结论 | 既有数学方法与独立证书重放 |

新增候选合同 `single-action-target-2` 通过 `reviewed_policy_target` 只传一份已审核政策意图，不再把旧兼容视图里的 `intervention` 和 `policy_assignment` 同时发给事实模型。

对于差值，程序只根据已审核的运算枚举排列第一端、第二端，保持 `FIRST_MINUS_SECOND`；不会按“启用”“新方案”或文字先后猜方向。自然语言到节点／编码的对应仍需从原文读取并独立核对。交接内容不是新事实来源、不是科学批准，也不能作为引用。

A0 已读材料继续通过 `information-inventory-1` 逐项交接；复查会重建目标和材料上下文，不沿用旧审批。该清单能发现遗漏，不保证模型一定填全。尚未读全、确实缺条件、错误引用和方法未覆盖分别报告。

## 模型输出和兼容视图分开

候选 `model-policy-output-1` 将固定政策均值和两政策差值的模型输出与旧接口字段分开：

| 位置 | 主政策怎样表示 | 谁负责 |
|---|---|---|
| 新模型回答 | 只输出 `semantics.intervention`；两政策比较另填 `comparator` 和运算方向 | LLM 读取原文，逐字段提供引用 |
| 旧接口需要的视图 | 从主字段原样复制出 `policy_assignment` | 确定性适配器生成；不是第二份模型判断 |
| 事实读取请求 | 只交接一份已审核的 `reviewed_policy_target`，R3 固定背景另行保留 | 公共交接代码；不是可引用的新来源或科学批准 |
| 旧客户端／旧会话 | 继续按创建时的协议处理 | 历史兼容模块，不自动迁移 |

新模型 Schema 不提供固定政策的旧别名槽位；如果模型仍返回该字段，即使与主字段完全相同也拒绝。主字段缺失时不会从别名或业务目标偷偷补齐。兼容视图原样保留状态、值和引用，原始回答不改写，回执注明 `compatibility_view_generated=true`、`alias_accepted_from_model=false`。其他目标中有实际含义的 `policy_assignment` 仍保留，不作全局删除。

本轮也只移除 Schema 中不可达的旧定义。同一请求的政策字段由 9 个减为 8 个，Schema 定义由 16 个减为 15 个；总请求仅缩短约 1.7%，不能据此宣称模型准确率提高。工作步骤资源不变，System Prompt 只替换一条与新输出规则对应的字段说明，没有加入针对业务题的新规则。

## 旧接口的兼容只做什么

`single-action-target-2` 及其旧兼容派生协议的主字段仍为 `semantics.intervention`。若旧客户端同时填写 `semantics.policy_assignment`，只有以下条件全部成立才接受这个冗余别名：状态相同、value 逐字相同、引用集合相同且无重复；主字段必须独立存在。引用顺序可以不同，不合并引用。这不适用于上面的新模型输出合同。

原始模型回答保留不变，投影视图与 `policy_action_projection.compatible_aliases` 明确记录兼容发生的位置和等价规则。不做自然语言改写匹配，不决定两个不同表述“应该是同一个意思”，不选择一个字段覆盖另一个。

不同值、不同状态、不同引用、缺主字段、错层级及其他额外字段仍阻断。`single-action-target-1` 的拒绝规则保留；此前失败记录不重新记为成功。新合同的 System Prompt 与旧单主字段合同相同，仅 Schema 增加明确的可选兼容位置；并未为测试业务增加提示语。

## 2026-11-01 本地验收

程序与兼容检查完成：172 项定向检查通过；31 种旧配置的请求逐字节不变。Wheel 已在源码外的新目标目录安装，207 个运行模块均从安装目录导入。四份预先固定的人工参考输入得到 POINT、PARTIAL、R3 POINT、缺条件 NEEDS_INPUT，前三项独立重放通过。该检查复用既有依赖环境，不称为重新创建全部依赖的干净虚拟环境验收。数学 Core 未变。

真实调用使用四份材料、三个业务情境，其中观察性业务有已采用／未决定交换性的条件对照；数学模板沿用已有能力，不是四个独立新数学场景。DeepSeek v4 Flash 与 LongCat 各调用 10 次，全部 HTTP 200。每条链最多允许一次 A0 或事实复查，没有自动重试、补条件或修改模型回答；调用期间源码与材料不变。审核由开发者对照合成原文完成，不是独立盲评。

| 指标 | DeepSeek | LongCat |
|---|---:|---:|
| A0 首答格式通过 | 4/4 | 4/4 |
| A0 首答语义及字段归属通过 | 2/4 | 2/4 |
| A0 首答引用覆盖通过 | 0/4 | 4/4 |
| A0 首答三项同时通过 | 0/4 | 2/4 |
| 计入允许复查后，A0 三项同时通过 | 2/4 | 2/4 |
| 已进入事实读取的首答三项同时通过 | 0/2 | 0/2 |
| 最终到达预期识别结果／规范缺条件结果 | 0/4 | 0/4 |

8 份 A0 首答都未填写旧主政策别名；一份 DeepSeek 复查又填回旧字段并违反状态格式，被拒绝。其他失败包括：编码或名单定义漏引、没有声明样本却填成明确缺失、将固定背景写成标准化分布、把已有均值顺序重复放到额外约束，以及事实说明中的未支持内容。LongCat 的一条随机业务主要被说明文字引用遗漏挡住；不能把它与“错误识别公式”等同。

本轮没有真实链路完成预期最终结果，也没有调用数学后端产生错误认证。负例在读取阶段提前阻断，**不记为已完成缺条件负例验收**。这里证明的是程序边界和兼容性仍有效，不能声称端到端稳定；本轮没有同题旧配置的真实对照，不能归因准确率涨跌。保留候选、不改变推荐起点，不追加提示语追求本轮通过。

本地逐题原文、原答、复查、审核与汇总保存在工作区的 本地实验记录（不分发），主要入口为 `REPORT_ZH.md`、`SUMMARY.json`、`INSTALL_ACCEPTANCE.json`。这些本地结果不属于发布内容。
