## 实际改动

新增可选 `network_fact_contract='network-source-selections-dependencies-1'`，实现见 [network_source_dependencies.py](../cfm_id_llm/network_source_dependencies.py)。它在原来的 Schema 上补充通用来源职责：

- 将“全部门店”展开为具体名字，要有范围声明和明确这些名字的名册；若同一原文已经写全，不要求多引一份文件。
- 将业务状态写成 own/exposure 编码，要同时支持本题选择的比较端和编码定义；只有定义不能说明用户选择哪端。
- 父记录、比较两端、信息记录各自负责自己写出的事实，不能自动继承别处的引用。

首次请求和显式复查从同一公开 Schema 提取来源职责。原局部效应复查没有发送这一组公开字段约束；现在选用本协议时，局部效应、固定政策和两政策比较都可发送对应来源规则。私有审核理由、参考值和预期识别状态不发送给模型。

没有增加答案字段或修改解析类型，没有自动补引用、改坐标或批准假设。旧协议保持原请求。比较读取在替换目标 Schema 后重新生成规则，避免携带单政策目标的过期路径。新协议改变请求绑定，旧批准不能直接沿用。

表中的引用覆盖检查关注是否选到支撑该字段所需的完整原文；即使来源选对，状态值仍可能读错，因此语义与来源必须共同通过。未通过整份审核的回答不继续执行。

最后一行明确要求“不使用减使用”。[现有入口文档](NETWORK_EFFECT_DISPATCH_ZH.md)原本已列出反向直接效应未接通，本轮预登记 POINT 超出了该范围，是**验收设计的范围判断错误**。原标签和不匹配结果保留，没有交换两端、修改题目、冒称数学不可识别或把停止计作识别成功。

因此新材料 LongCat 八次预定完整尝试中，首读至最终预期状态严格匹配 **4/8**：两个 POINT、两个正确缺项停止。不能把事实严格的 5/7 写成全链路成功率，也不能用后续重读替换首答成绩。

另有四次已知材料控制：使用同一真实审核 A0，旧／新事实请求各两份；旧两份均有引用遗漏，新两份有一份整份通过，另一份经一次定位重读通过。这两份执行为 POINT，并分别精确枚举 32／64 个安排及完成证书重放。它们不计入新题分母。此小对照只支持局部改善；A0 配置未改、材料不同，不能把本轮 A0 7/8 与上一轮 4/8 直接解释为本改动的效果。
