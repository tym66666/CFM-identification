# LIT-DAG-01 案例设计说明

## 1. 原题怎么来的

把 Pearl 的后门准则映射到一个合成销售团队业务场景：

- \(Z\)：是否资深员工（工龄超过五年）；
- \(X\)：是否参加培训；
- \(Y\)：季度业绩是否达标。

图：

```text
Z → X
Z → Y
X → Y
```

目标是：

\[
p(y\mid do(X=x)).
\]

\(Z\) 满足后门准则，所以：

\[
p(y\mid do(X=x))=\sum_z p(y\mid X=x,Z=z)p(z).
\]

## 2. 为什么选这个案例做 DAG 模板

- 后门准则是仓库当前已支持的能力；
- 三变量图小，公式容易人工核对；
- 可以同时检查：
  - 图是否被正确读取；
  - 调整集合是否满足后门条件；
  - 公式是否按 \(p(z)\) 加权，而不是按治疗组分布加权；
  - 缺失图条件时是否停止；
  - 控制治疗后中介时是否拒绝。

## 3. 两个改动版

### 缺条件版

删除“所有共同原因均已列出 / 图完整”的声明。

预期：

- 不能确认 \(Z\) 是否阻断全部后门路径；
- 不能确认没有未观测共同原因；
- 系统应 `NEEDS_INPUT`，而不是默认图完整。

### 目标变化版

把 \(Z\) 改成“本次培训之后是否取得资深资格”，即治疗后的中介；业务方要求控制它来估计直接效应。

预期：

- \(Z\) 是处理 \(X\) 的后代；
- 不满足后门准则；
- 系统应 `UNSUPPORTED`，原因应是调整集合包含处理后变量；
- 不能把控制中介后的公式当成总效应。
