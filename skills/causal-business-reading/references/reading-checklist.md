# 直接审阅业务时核对什么

已有系统 Schema 时优先使用它；本表用于没有运行请求的业务草稿，不是第二套 JSON 或批准规则。

| 关注点 | 要保留的区别 |
|---|---|
| 用户请求 | 单个方案的均值、两端差值、同伴影响、干预分布、策略选择分别表达；条件缺失不抹掉已知目标 |
| 比较 | 保留两端、方向与共同条件。显式 X 减 Y 按原文；从 A 到 B 的增加为 B−A、减少为 A−B，允许负值；未定不猜 |
| 对象与网络 | 研究名册、使用名单、评价名单、记录覆盖分别核对；对象合作网络不是变量因果 DAG |
| 数据与信息 | 样本记录、样本统计、符号总体算子、具体总体数值分开；表头解释坐标，不证明覆盖完整 |
| 科学条件 | 已采用、拟采用、未定、拒绝、冲突分别保留；暴露定义不推出均值充分性，条件声明不是批准 |
| 来源 | 本字段实际写出的名称、时点、编码、状态和范围均需有来源。不要因编号存在就认定其支持主张 |

用业务语言询问真正影响目标或条件的缺项，不要求负责人先懂 R1a/R2/R3。不要把已知信息重复扩写到不同字段，也不能为了简洁删除真实条件。运行格式中的字段归属、引用依赖与未知结构由代码合同维护，不在这里复制。
