# 网络业务字段职责检查材料

`public.json` 中每个案例只包含业务问题与原始材料。包含原配送站失败题、明确以检修任务单为单位的反向例、单份混合材料中的服务点例，以及样本/总体、科学界限缺失、科学条件拒绝和额外约束的负例。业务题描述日常决策；附件中的研究条件是显式合成设定，不由系统替企业批准。

`research_references.json` 供本地评审与独立数值检查使用，不能作为模型输入，也不能替换实际模型回答。完整原题与逐项引用需要独立审查；已读错的案例属于开发集，不能称为未见题总体准确率。几道条件变体共用数学结构，不能算作独立数学场景。

读取通过、输入条件齐全、原生识别和证书重放分别记录。负例应保留未决定/未提供/拒绝或真实额外条件，不能为了获得 POINT/PARTIAL 删条件。可观察总体量的真实区间属于已有信息，带抽样误差的置信区间仍是样本信息；潜在结果在各干预安排下另行采用的界限属于科学限制。

本组材料不增加数学 Core 能力。关于不完全观测总体信息的题用来检验读取与保留边界，当前数值入口未实现相应信息类型时应停止，不把范围的中点或端点当成已知总体均值。

参考标签勘误：明确拒绝全安排均值充分性的情形应记为 `ADAPTER_NOT_CONNECTED`（当前所需模型未被接受），与尚未决定时的 `NEEDS_INPUT` 区分。首轮冻结标签曾误写为后者；原始标签和不一致记录保留在包外试验档案，没有追溯改成预测命中。参考结构中移除了继承自基础案例而不适用于条件变体的题面、区间和数值列表，实际业务原文始终以 `public.json` 为准。
