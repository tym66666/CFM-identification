# CFM Identification — Task 6 可复现评测包（2026-11-04）

> 基于用户提供的 9 页学生任务书及公开仓库 `zzyyLOGIC/CFM-identification` 在 2026-11-03 左右的推荐读取配置编写。**此包没有调用真实 LLM**，没有替代项目的事实读取、科学审核与数学证明，也没有经第二位审读者认证的“正确率”。

## 一句话理解

你的任务是测量“系统有没有正确读懂业务”，比较可核验的 Prompt/Skill 读取方案，向项目组交一份可复现实验及配置建议；不是修改因果识别数学方法或让 LLM 宣称自己证明了定理。

## 已打包的文件

- `materials/T6-*.json`：12 个独立场景的完整版和条件缺失／矛盾版，共 24 份**自拟业务测试材料**。10 个网络情境、2 个变量因果图情境。
- `references/T6-*.gold.json`：目标类型、比较方向、评价名单、时点、背景和负例的**作者参考草稿**。这些参考**尚未通过独立审读**，不能当成已认证 Gold。
- `scripts/run_experiment.py`：真实仓库 `project` 配置、`business_intake` 和 `OpenAICompatibleChatProvider` 上的 A0 读取对照；默认不联网，超调用预算将拒绝。
- `scripts/score_experiment.py`：格式与业务问题数的客观统计＋独立人工复核表＋配对总结；不以 JSON 通过代替语义通过。
- `scripts/fact_stage_ledger.py`：逐问真实事实读取/数学执行的补充审计台账，只有审核人实际填入记录才产出全链路指标。
- `docs/评测设计与评分口径.md`：分层分母、人工审核规则、重复运行及成本、实验局限、留出隔离方法。
- `tests/test_dataset.py`：材料完整性和密钥隔离的纯离线单元测试。

## 先跑原仓库，无需 API

在 Windows PowerShell 上安装 Python 3.11+ 与 Git，再执行：

```powershell
git clone https://github.com/zzyyLOGIC/CFM-identification.git
cd CFM-identification
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m cfm_id.project config
.\.venv\Scripts\python.exe -m examples.student_handoff --allow-synthetic-reviews --output outputs\first_run
```

这三个示例的回答是预先固定的模拟夹具，不是 LLM 的真实成绩。若克隆、安装失败，先按仓库 `docs/TESTING_ZH.md` 和环境信息排查；不要擅自改数学核心。

## 把本包复制进现有项目

解压本 ZIP，假设解压后的文件夹名为 `CFM_Task6_ResearchPack`，在**仓库根目录**执行：

```powershell
Copy-Item -Recurse -Force "C:\你的下载路径\CFM_Task6_ResearchPack" ".\evaluation\task6"
.\.venv\Scripts\python.exe -m unittest discover -s evaluation\task6\tests -v
```

这是新增 `evaluation/task6/`，不会覆盖当前公共读取配置或数学模块。

## 第一次只准备请求，不联网、不花 token

```powershell
.\.venv\Scripts\python.exe -m evaluation.task6.scripts.run_experiment `
  --subset dev --ids N01 --output outputs\task6_prepare_N01
```

将准备 4 项 A0 请求：N01 完整/缺项版，各用 Prompt-only 和 Prompt+Skill 两套真实协议。输出目录必须不存在。检查：

- `outputs/task6_prepare_N01/manifest.json`：git SHA、当前推荐配置、Skill SHA、请求列表及 planned_calls。
- `outputs/task6_prepare_N01/private/`：每份**完整真实请求**和哈希；离线阶段 `raw_response_saved=false`。
- `outputs/task6_prepare_N01/summary_status.json`：应显示 `NO_API_CALLS`，不应出现准确率。

## 使用自己的授权 API 运行一个最小真实对照

请先从学校网站确认 DeepSeek 接口的真实 API Base URL、模型标识和调用额度。`https://newapi.sufe.edu.cn/` 是学校提供的网址，**不等于已经核实的 API base-url**。项目提供者采用 OpenAI-compatible Chat Completions，并从 `CFM_ID_LLM_API_KEY` 或 `OPENAI_API_KEY` 环境变量读取密钥。

配置环境变量后，替换下面的 `BASE_URL` 和 `MODEL_NAME`：

```powershell
.\.venv\Scripts\python.exe -m evaluation.task6.scripts.run_experiment `
  --live --allow-external --allow-material-sharing `
  --subset dev --ids N01 --repeats 1 --max-calls 4 `
  --base-url BASE_URL --model MODEL_NAME `
  --thinking disabled --max-tokens 16384 `
  --output outputs\task6_live_N01_001
```

脚本默认 nonstream、JSON 模式、无自动重试；记录实际 raw、超时／JSON／协议错误和模型的 token 使用量。**不要把有密钥、原始响应或真实业务资料的 `private/` 上传到公共 GitHub**。

## 生成复核表、评分

```powershell
.\.venv\Scripts\python.exe -m evaluation.task6.scripts.score_experiment `
  --run outputs\task6_live_N01_001
```

生成 `review_template.csv`。请让另一位研究者查看原文、参考、原始模型回答并在每行填入 `PASS`、`FAIL`、`UNCERTAIN` 或 `NOT_REVIEWED`，填写 `reviewer_id`、引文位置和原因。审核完成后：

```powershell
.\.venv\Scripts\python.exe -m evaluation.task6.scripts.score_experiment `
  --run outputs\task6_live_N01_001 `
  --reviews outputs\task6_live_N01_001\review_template.csv
```

报告有全尝试分母、格式通过、已审核 A0 语义准确率与同题配对差；**如果未审核完，不会给出整个测试集的正式 A0 准确率**。

## 开展完整实验前的冻结

先跑 N01（4 次），按 `docs/评测设计与评分口径.md` 检查协议、令牌用量和审核表。然后冻结开发好的候选与配置：开发集 8 场景 × 2 版 × 2 协议 × 2 轮共 64 次 A0，留出集 4 场景 × 2 版 × 2 协议 × 2 轮共 32 次 A0。运行留出集必须加 `--frozen-run`，并检查 `git_head`、材料与 Prompt/Skill 摘要没有改动。只有经过实际人工审读的 `references/` 才能用于正式统计。

对全链路结果，在通过原仓库的业务审核后继续原有事实读取、科学审核、数学执行和独立证书重放流程；该过程**未集成进 `run_experiment.py`**。用下面的命令生成逐问台账，并且只能填入亲自检查的真实结果：

```powershell
.\.venv\Scripts\python.exe -m evaluation.task6.scripts.fact_stage_ledger `
  --run outputs\task6_live_N01_001
```

填完后再运行相同命令加 `--ledger outputs\task6_live_N01_001\fact_stage_template.csv`。不能仅因为 A0 JSON 和引用合法就将 `first_pass_full_chain_correct` 标为 TRUE。
