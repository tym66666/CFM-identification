# PR 标题

任务6：LLM业务理解

## 问题与最终行为

原有评测主要检查业务读取和输出格式，尚不足以判断从业务材料出发能否得到正确的识别结果。本次补充代表性端到端试点：

- 从业务原文和附件出发，经过模型读取、来源与条件审核、识别计算及证书重放。
- 区分缺条件和材料冲突，新增对应题目及预先准备的业务答复。
- 分别记录格式、业务理解、引用和最终识别结果；首答、复查及审核介入分开统计。
- 评分依据实际执行结果，审核阻断不计为全流程成功，程序不支持不计为数学非点识别。

针对冲突材料，新增审核确认后的项目追问入口：要求当前字段审核已拒绝、审核者提供两处可定位原文及冲突说明；入口只提出澄清问题，不修改模型答案、不批准科学条件，也不调用数学后端。

## 数学与接口

复用已有的点识别、部分识别及证书重放能力，不新增数学方法或放宽审核规则。

新增非默认提示配置，针对引用不足、对象网络与变量因果图混淆、材料冲突遗漏补充说明。该配置复用现有输出合同，新增提示纳入请求绑定；默认配置不变。

部分识别题另通过独立枚举核对限定模型下的参考区间 `[3/7, 4/7]`。

## 实际验证

- **执行的命令和结果：**任务六离线测试 21 项通过；在 Pydantic 2.14.2 环境下，相关合同及交接测试 11 项通过。
- **正例、缺项／拒绝与证书重放：**点识别和部分识别分别经真实模型重试或复查，得到 `POINT` 和 `PARTIAL [3/7, 4/7]`；均从保存的模型候选及审核记录重建输入，并重新重放证书。缺条件题在事实复查后返回 `NEEDS_INPUT`。
- **冲突题：**模型回答遗漏相反材料，字段审核拒绝后，项目入口根据审核者定位的原文生成冲突追问，返回 `CLARIFICATION_REQUIRED`，未调用数学后端。这是审核介入后的结果，不计为模型首答成功。
- **真实 LLM 首答／复查：**DeepSeek V4 Flash 在相同四题上对基线和候选配置各尝试四次；两组各返回两次、超时两次。Qwen3.8-27B 在冲突题上的两次配置对照均超时。现有样本不足以证明候选配置优于基线。
- **兼容性与安装检查：**相关测试在符合仓库依赖的环境中执行；未声称全仓库回归通过。
