# 任务 6：研究设计、审核责任与判分口径

> 本文保留初始设计；“未调用”等进度描述为当时状态。2026-11-06实际状态、已修复问题与待办以任务6代码审查与待办.md及README_ZH.md为准。

## 与项目边界一致的研究问题

- **主要研究问题**：真实业务材料下，`target-first-operands-1`（Prompt-only 比较臂）与 `target-first-skill-1`（当前维护方案）在 A0 首读时，哪一项对目标、两端、名单、背景、来源的理解更完整？
- **明确限制**：这两个方案除 Skill 以外也改变了 Schema / 局部验证约束，因而是**两套读取方案的综合对照**，不是对 Skill 本身净效应的因果估计。
- **次要研究问题**：格式通过率、缺项/冲突正确处理率、来源语义支持率、token 与调用次数、重复运行波动。完整链路只能在后续真实事实读取、科学审核、数学执行和证书重放后单独报告。

## 预注册式实验方案

1. 12 个独立的自拟场景：N01–N10 网络，D11–D12 变量 DAG。每场景 `full` 与 `changed` 两个版本，共 24 份业务材料；不是 24 个独立情境。
2. N01–N08 为开发场景；N09–N10 与 D11–D12 为**留出场景**，共 4 个独立情境／8 份材料。在看留出模型回答前冻结候选、评分规则、测试材料与模型条件。重试或重跑不是新情境。
3. 每份案例都有独立 `sources`，其文本不会包含 `references/` 的参考结论。`references/` 仅供离线审核，当前状态全为 `AUTHOR_DRAFT_PENDING_INDEPENDENT_REVIEW`，需要另一名研究人员签名复核后才可用于正式准确率。
4. 固定模型、采样/思考设置、超时、JSON 模式、输出预算、材料、审核判据与代码版本。两臂不同的地方是其真实受控协议——`a0_response_contract`。输出记录真实请求摘要、完整私有请求、原始 JSON、模型用量、结果及错误码。对同一情境使用交替调用顺序，避免始终让其中一组先调用。
5. 对 `full` 和 `changed` 均测试，不将故意缺失/矛盾材料的“错误解析而停止”算作正确识别缺项。尤其不能把 A4 总体信息与有限样本混淆，不能把暴露定义当成充分性许可，不能偷换差值方向。
6. 如果开发题失败，只可在下一次**新配置版本**中调整 Prompt/Skill；不能把看过的题作为留出题。对照期间不改参考答案、脚本或模型参数。
7. 学校 DeepSeek 网关的完整 API base URL、模型名、用量限额和账户授权应核实；仓库中的 Chat Completions 提供者读取环境变量 `CFM_ID_LLM_API_KEY` 或 `OPENAI_API_KEY`，**不要把密钥写入案例、仓库或原始输出**。

## 真实评价的四层分母

| 层级 | 合格条件 | 正式分母 | 此包进度 |
|---|---|---|---|
| (1) 请求 / 格式 | 请求可达、JSON 为对象、项目解析/协议符合要求 | 全部**计划且实际尝试**的 A0 请求，传输失败计失败 | 提供真实 runner，未调用 |
| (2) 语义 / 引用 | 目标、被减数、减数、评价人群、时间、背景、数据范围等忠实于原文，引用确实支持 value | 全部 A0 尝试；参考需独立审读 | 提供审核模板，尚待独立审读 |
| (3) 缺项 / 追问 | 真正定位原文没有给出的条件或其矛盾；解析坏了不算正确缺项 | `changed` 的全部对应尝试 | 提供负例和审核模板 |
| (4) 最终执行 | 经目标与来源审核、A4/A5 科学审核，点识别或区间被独立验证；负例正确停止 | 全部首次 A0 业务尝试，附逐问与整题口径 | 未实际运行全链路，提供逐问记录表 |

同时分别报告「格式合法」「首答语义正确」「追问正确」「完整执行正确」「错误认证次数」。`WRONG_CERTIFICATION` 应逐例列出，禁止平均分掩盖。

## 人工审核如何执行

拿到 `review_template.csv` 后，独立审阅者必须打开对应私有文件夹的 `raw_response.json`、`a0_inspection.json`、`request.json`，并同时阅读 `materials/<case_id>.json` 和 `references/<case_id>.gold.json`：

- 判断每一条 claim 的 **value 是否与原文一致**。有 ref 不等于 ref 支持该结论；同一个 doc 的别处提到类似词也不能替代原文依据。
- 核对 `query.kind`、`comparison_order`、两个操作数，以及多问是否漏题；**减少量和增加量的正负方向不可颠倒**。
- 核对原始实验名单、目标评价名单、背景条件、汇总权重、结果时点；不要根据未来政策补造历史随机化。
- 判断缺条件版是否真的揭示了缺少什么；不能把格式损坏或错误拒绝当作成功。若 A0 并不负责读取 A4/A5，只评它是否无越权主张，A4/A5 另在事实阶段判断。
- 评判 `PASS/FAIL/UNCERTAIN/NOT_REVIEWED`，填写 reviewer_id、证据位置与归因。`UNCERTAIN` 不得视为通过。独立参考仍未经审读时，暂不发布“正式准确率”。

## 实验成本

推荐先对 N01 的完整及变体各跑两臂 1 次，即 **4 次 A0 API 请求**。若每份材料、模型、接口均无误，再跑开发集 16 份 × 两臂 × 两轮 = **64 次 A0 请求**；留出集 8 份 × 两臂 × 两轮 = **32 次 A0 请求**，合计 96 次 A0 请求。这还**不包括**每个子问的事实读取、主动重读、重试和人工审核成本；不可把只有 A0 的 96 次写成完整链路成本。

`run_experiment` 默认调用上限 8、默认离线；真实调用必须显式 `--live`、`--allow-external`、`--allow-material-sharing` 和相应 `--max-calls`。重复轮次不同请求不能当作新的业务情境；失误重读另记。

## 安全与隔离

- 原始完整请求和原始答案只保存在 `outputs/.../private/`（本机受控目录）；交到 GitHub 的只能是脱敏样本、独立已审参考及汇总。
- 从模型输入中完全排除 `references/`。报告内写清当时的 Git SHA、Prompt SHA、Skill SHA 与请求 SHA。
- `api_key` 只通过环境变量读取，模型输出和服务响应元数据中不应保留 authorization 头。
- 学术假设是否成立由研究者决定；`business_intake.inspect` 只给读取／复核状态，不负责证明数学正确性。
