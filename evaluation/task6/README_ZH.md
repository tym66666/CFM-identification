# 任务6：LLM业务理解对照评测

## 主分支接纳范围（2026-11-11）

本目录作为评测研究资料接纳，**不替换项目默认 Prompt / Skill**。`target-first-skill-guarded-1` 仅供显式对照；目前没有充分证据证明它提高了首答全链路成功率。

- 本仓库可独立检查：材料与参考的结构、评分分母、请求绑定、独立小图参考计算、拒绝与追问边界。
- 下方及 `results/` 的真实模型结果为**提交者报告**。公开仓库没有对应全部原始答复、审核记录和证书，维护者未独立重放这些历史模型结果。提交者声称独立复核，不等同于本轮已核验其原始证据。
- `pilot_fullchain.py`、评分与台账工具可用于新实验；`audit_*`、`review_pilot_*`、`replay_point.py`、`replay_partial.py` 等含固定题目/哈希的脚本用于对应历史运行检查，不是通用自动语义审核器。不得替换哈希后冒称原始模型成功。
- `cfm_id.intake_conflict_review` 是研究者明确拒绝并定位冲突后的停止接口；程序检查来源和审核绑定，不判定自然语言矛盾，也不自动修订、批准科学假设或恢复整个网页流程。一个文件内的不同来源段落也可形成冲突。
- 新实验默认采用已绑定的候选配置；`v1/v2` 保留为历史对照。原始记录应受控保存并按真实调用、重读、人工修订分别计数。

下列日期段落是历史报告；与本节不同的证据状态，以本节为准。

参见[端到端试点报告](results/20261108/端到端试点报告.md)、[原题缺项与冲突复核](docs/原题缺项与冲突复核.md)和`pilot_cases/`。针对4个业务题进行了真实模型读取、实际字段拒绝、提示对照及单题重读；真实模型结果尚未进入事实读取、识别计算或证书重放，离线教学例不能计入真实模型全链路成绩。已发现的源引用、变量图角色和材料冲突错误均保留。

`pilot_fullchain.py`记录真正发给模型的提示与哈希；旧版实验追加文本不在项目原请求绑定内，因此旧版候选只可用于读取对照。本次起默认的 `--candidate-version bound` 使用已注册的可选配置，提示纳入请求绑定，仍须逐级审核。`pilot_recheck.py`使用项目原生、绑定的重读机制；第二次重读输出停在变更审核。`verify_final.py`检查已记录的实际后端结果及证书摘要，**不会自己重放证书**。`fact_stage_ledger.py`不再允许仅凭勾选把正例计为成功。

试点真实调用、审核原件存放在本地`outputs/task6_pilot_*`；提交时只包含脱敏汇总。试点参考尚未独立签审，模型和AI辅助核对不能伪装成人工认证。格式、语义、引用和最终结果分开报告，候选配置未替换默认配置。

离线验证：`python -m unittest discover -s evaluation/task6/tests -v`。重新试跑需用户授权及环境变量`CFM_ID_LLM_API_KEY`，例如：

```powershell
python -m evaluation.task6.scripts.pilot_fullchain --output outputs/task6_new_pilot --model deepseek-v4-flash --base-url https://newapi.sufe.edu.cn/v1
```

该命令默认发送4题×2方案共8次A0请求；输出目录必须不存在。默认使用绑定候选；`--candidate-version v1` / `v2` 仅供显式复现历史读取实验，不可据此进入后续审核与识别。事实审核和数学执行可按`scripts/n01_fullchain.py`分步操作，不能把旧版实验提示伪装成项目已绑定请求。原始材料为自拟公开题，私有请求和答复不要提交。
